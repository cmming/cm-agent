# 文档治理采用稳定路径、固定职责与两类事实依据

决定日期：2026-11-13；决定：已采纳。来源为用户在本次讨论中对 Q1–Q6 及具体实施边界的明确确认。

历史工作包保留原路径，通过索引逻辑归档。移动到归档目录并保留旧路径指引虽能直接区分目录，却会增加链接维护和追溯成本；现有大量跨主题引用使稳定路径更有价值，代价是文件数量不减少，导航需要维护。

保留六份工作包的固定职责，以账本作为任务状态、验证证据及归档记录的唯一来源。当前使用说明、需求设计、实际改动和执行证据分别维护；术语表定义概念，ADR 解释少量重要取舍。这样保留追溯能力，同时通过短文档与引用控制重复。

实际行为按对应代码版本、实际生效配置和可重复验证判断；预期行为按用户确认的需求、设计和 ADR 判断。两者不一致时记录差异，再判断实现缺陷、文档过期或需求变更，避免以实现覆盖要求，或以旧设计冒充运行事实。

归档以本包责任范围完成、明确取消或剩余事项逐项移交为依据。归档不等于提交、发布或全环境验收；历史事实保留形成时语义，后续变化和重要纠错带日期、原因与依据。

具体执行要求由[产物契约](../../.agents/skills/requirement-workpack/references/artifact-contract.md#工作包归档与恢复)维护，术语见[术语表](../../GLOSSARY.md)。本 ADR 不承载工作包实时状态。
