# docs 可用性复核设计

日期：2026-11-17；主题：`docs-usability-review`；修订：R2（2026-11-17）；模式：`mode=default`。

用户希望分析并优化 docs。此前全量复核已维护历史索引，本轮以使用者查找效率与配置事实为重点，不重做历史归档。

## 范围与决定

- T0：先检查既有工作树及 2026-11-13 复核记录，保留既有修改。
- T1：使用场景入口及长文内部锚点，保留已有章节和链接，不迁移文件。
- T2：按代码和配置区分属性初值、提交基线、带日期的工作树快照及目标环境；工作树文件不代表服务正在运行，历史证据不替代运行验证。
- T3：仅做文档及本地链接验证。历史完整性、线上部署、业务实现和重新执行历史验收不在范围。

## R1 范围调整（2026-11-17）

| 差异 | 类型 | 变化与依据 | 影响 |
|---|---|---|---|
| D1 | 新增 | 用户要求全面复查 docs 的过时、矛盾和遗漏，范围从入口与配置扩大到现行使用文档、历史入口和本地引用 | 新增 T4–T6；不把静态检查称作运行验收 |
| D2 | 澄清 | 导入资料 T9/T10 旧状态与后续代码接线需要分时点说明，整体验收独立核定 | T4、T5；保留旧阶段证据与未完成门禁 |
| D3 | 澄清 | 历史状态目录是带日期快照，账本记录任务状态、Git 记录提交与工作树状态 | T5；保留旧统计与分类 |
| D4 | 新增 | 安全复核发现 JWT 声明验证边界未说明，文件产物协议存在原始异常日志与脱敏规范的差异 | T4、T5；如实说明并保留代码问题，代码修复不在本轮文档范围 |

R1 的直接关联入口包括根 README；只做必要的一致性修正。历史发布条目保留原文，必要时追加后继说明，不批量重写历史。外链可达性与真实服务、浏览器、数据库和 Provider 验收不属于静态复核结论。

## R2 重复内容整理（2026-11-17）

| 差异 | 类型 | 变化与依据 | 影响 |
|---|---|---|---|
| D5 | 新增 | 用户要求继续检查和优化重复文档模块，新增现行说明的重复分析和定点合并 | T7–T9；不改变业务行为 |
| D6 | 澄清 | 按文档职责设置单一详细来源：配置说明负责参数，工具开发指南负责 HTTP 参数合同，运维说明负责运行步骤，Harness 保留设计与适用边界 | T8；必要的安全提醒和独有信息不删除 |
| D7 | 澄清 | 历史账本、发布说明、归档快照和不同视角导航不是可无痕删除的重复 | T7–T9；保留路径、标题锚点及形成时结论 |

本次保留不同读者确需的简明摘要；当迁移后仍有独有的操作条件或限制时先保留或迁移，再缩减重复内容。用户要求忽略的既有事项不属于本轮范围。

假设：用户要求直接改善文档，无需重排全部历史资料；已有配置改动属于用户工作，不能重置或调整。验收以清单各项为准。
