# 会话聊天均衡优化实施：设计

日期：2026-10-10；主题：chat-page-ux-delivery；修订：R0；工作模式：mode=default。

用户已要求按照原执行提示词继续实施。本包为独立实施记录，引用[原分析提示词](../prompts/2026-10-10-chat-page-ux-prompt.md)与[原分析清单](../checklists/2026-10-10-chat-page-ux-checklist.md)，原分析六份文档保留历史状态。

已确认 D1：均衡优化，保留中文管理控制台风格，不新增后台业务能力。已确认 D2：Enter 发送、Shift+Enter 换行，中文组合输入防误发。常规工程细节自主处理；未改变这两个决定。

## 背景与目标

原聊天页的空审批历史和高输入区挤压消息阅读，连续 delta 强制滚底，发送前清空输入，手机列表与消息争用高度。目标是在既有受控工作台内让阅读、输入和运行状态容易操作，复用现有会话、审批、停止及文件治理能力。

## 采用方案

T1：桌面以视口高度分配会话列表和消息工作区，正文独立滚动，输入收为 48～144px 的内容自适应区域；待审批时限制输入上限。短视口允许面板滚动。手机保留导航，紧凑标题一行，通过“会话与 Agent”切换列表，列表有固定可用高度，关闭后消息区重新使用空间。

T2：本地过滤已加载标题，明确显示数量和最多 50 个的限制，按更新时间分组；完整标题通过 title 与键盘焦点展开查看。空会话也保留真实标题。

T3：离底部超过 48px 暂停跟随，回到最新恢复；终态回读以消息标识和相对视口位置恢复。异步文件挂载使用相同跟随规则。复制正文只取 TEXT，代码只取代码节点，不用 HTML 拼接内容。

T4：Enter 发送、Shift+Enter 换行，组合输入结束与确认回车分开保护。草稿和提交快照仅存在当前页面内存，按 Agent/会话隔离；导航、退出或刷新清空。收到 started/completed/approval-required 清空已接收输入；明确拒绝保留可编辑输入；无法确认写入时保留并锁定，只查询状态。新增同文 USER 消息可以确认已写入，旧同文消息或其他浏览器的活跃 Run 不能误清快照。

T5：审批历史外层默认折叠，空历史一行，读取失败自动展开并保留具体原因和原错误码/编号；既有运行内历史仍保留。待审批区有独立限高滚动，不弱化权限。停止按钮显示文字，既有等待与部分输出行为不变。

T6：共享脚本按 v2 聊天特征节点启用，旧版返回原路径；所有 v2 入口共享资源版本一致，避免文档内导航混用缓存。补真实控制器测试、共享页面回归与模拟浏览器。T7 保留实机与真实环境补验收。

## 安全与边界

不新建后台接口、领域服务或迁移，不修改租户、权限、审计、canDecide、受控下载、Markdown 协议过滤。剪贴板拒绝不曝光原始异常，不虚构服务端 errorId。没有持久化重放队列或自动补发。

当前没有服务端消息幂等编号；页面刷新会丢失未确认快照。GET 长期未读到新增用户消息时保守保持锁定，不能直接证明未写入。受最多 200 条历史限制影响的极端长会话需在真实环境核对。更强恢复能力属于后续后台需求，不纳入本次。
