# 文档治理规则落地：设计

日期：2026-11-13；主题：`documentation-governance`；修订：R0；模式：`mode=interactive`。

## 背景与目标

仓库已有当前使用说明、六类工作包、主题索引及历史 Git 快照。本次在用户分轮确认后，将历史归档方式、文档职责与权威来源固化为一致规则。

前置记录：[2026-08-07 四文档治理设计](2026-08-07-superpowers-documentation-governance-design.md)、[2026-11-13 文档整理账本](../progress/2026-11-13-doc-organization-followup-ledger.md)。旧治理包保存当时的四文档决定，本次独立六份工作包不回改旧记录。

## 已确认决定

| 决定 | 用户选择与取舍 | 影响 |
|---|---|---|
| Q1 | 保留原路径，通过索引逻辑归档；不采用移动目录并维护旧路径指引 | 链接稳定，文件数不减少 |
| Q2 | 保留六件套固定职责；账本唯一保存状态和证据；使用说明、ADR 与术语表各司其职 | 避免多处复制实时状态 |
| Q3 | 分别判断实际行为与预期行为；冲突先记录和定性 | 不以代码自动覆盖需求，不以旧设计代替现状 |
| Q4 | 责任范围完成、明确取消或逐项移交后才归档；日期和提交状态不能单独作为依据 | 缺少依据的历史主题保持归档状态待核实 |
| Q5 | 本轮完善规则、入口和一份已核实归档样例；新增必要术语、一份 ADR 与独立工作包 | 不批量重写历史正文或补齐旧六件套 |
| Q6 | 保留历史语义；变化补后继说明，错误带日期和依据定点修正 | 原测试数字、验收范围和重要决定可追溯 |

用户进一步确认 16 份具体文件、同一需求的恢复方式以及不提交、推送、部署的边界。当前模式为交互模式，已确认事项直接实施，新的范围取舍仍由用户决定。

## 方案与边界

归档和恢复是账本事件，目录只投影其结论。首个归档样例采用 `doc-organization-followup`：责任范围是文档整理与复核，不将 14 个未能核验的公共外链写成已验证有效。本次规则是独立需求，不伪装为该包未完成事项的移交。

术语表只收录本项目文档治理概念；ADR 保存稳定路径与两类事实依据的原因；详细记录要求集中到产物契约，AGENTS 和技能入口提供简明规则和读取条件。

本工作包登记为当前，任务完成后不自动作归档决定；本轮仅核定前一整理包。其他主题没有充分归档依据时只提供待核实导航，不推断业务状态。任务编号统一为 T0–T6，实施边界和验收以[清单](../checklists/2026-11-13-documentation-governance-checklist.md)及[计划](../plans/2026-11-13-documentation-governance.md)为准。
