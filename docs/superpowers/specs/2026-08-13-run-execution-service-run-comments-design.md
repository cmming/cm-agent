# RunExecutionService.run 业务流程注释设计

## 背景

`RunExecutionService.run` 是 Agent 单轮运行的核心编排入口，串联 Agent 与模型配置校验、工具授权筛选、运行记录持久化、运行时执行、异常收口和响应脱敏。当前方法仅有概括性 JavaDoc，阅读者需要逐行推断各阶段的业务目的及异常分支差异。

## 目标

- 通过中文注释清晰说明 `run` 方法的完整业务流程。
- 解释关键步骤的业务目的，以及不同异常类型采用不同收口方式的原因。
- 保持现有代码逻辑、接口、异常类型和运行结果完全不变。

## 范围

- 扩展 `RunExecutionService.run` 的方法级 JavaDoc，概括主流程和失败处理原则。
- 在方法内部的关键阶段前添加简洁的中文行内注释：
  1. 在当前租户内校验 Agent 和模型配置。
  2. 根据授权关系筛选本次运行可用工具。
  3. 先创建 `RUNNING` 记录，建立后续持久化与诊断所需的运行标识。
  4. 组装运行请求并调用 `AgentRuntime`。
  5. 区分审计/数据库异常与普通运行时异常，执行相应失败收口。
  6. 将运行结果和工具调用持久化，并使用持久化终态构造脱敏响应。

## 非目标

- 不修改业务逻辑、异常映射、日志内容或事务边界。
- 不重构 `run` 方法或其私有辅助方法。
- 不新增测试；本次只有注释和过程文档变更，不影响可执行行为。
- 不修改 README、生产配置或发布说明，因为对外行为没有变化。

## 方案

采用“方法 JavaDoc 总览 + 关键阶段行内注释”的方式：

- JavaDoc 说明该方法在控制器完成入口权限校验之后承担的编排职责，并描述成功和失败两条主路径。
- 行内注释放在业务阶段边界之前，解释一组代码的目的，不逐行复述 Java 语法。
- 异常分支重点说明：审计和数据库异常保留原异常语义；普通运行时异常记录可关联诊断、尝试完成失败状态与审计，再转换为受控异常。
- 注释保持中文、简洁，并使用项目现有领域术语，如 `RUNNING`、Agent、Runtime 和 ToolCall。

## 约束

- 不改变任何可执行语句，确保生成字节码的业务部分不受影响。
- 不在注释中写入密钥、内部地址或其他敏感配置。
- 保持当前多租户、工具授权、严格审计和错误诊断语义准确。
- 保留工作区现有配置文件修改，不纳入本次变更。

## 验收标准

- 阅读 `run` 方法即可按顺序理解从资源校验到脱敏响应的完整流程。
- 注释准确区分三类异常处理路径及其失败收口方式。
- `RunExecutionService.java` 除注释外没有代码变化。
- 相关模块编译或测试通过；若仅执行针对性验证，需在进度账本和最终说明中记录范围。
- 同主题计划、实现说明和进度账本与本设计保持一致。
