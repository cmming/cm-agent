# 会话停止本轮实施：设计

日期：2026-10-10；主题：`chat-stop-delivery`；修订：R0；模式：`mode=default`。独立实施包引用原 [需求设计](2026-10-10-chat-stop-design.md)，原 R0 历史不改写成实施完成。

## 目标与决定

| 决定 | 问题及候选 | 状态与用户选择 | 影响 |
|---|---|---|---|
| D1 | 问答所在入口 | 已确认：CM Agent 控制台聊天 | 不扩展需求问答或独立 TEST |
| D2 | 真暂停续跑 / 停止本轮 | 已确认：停止本轮、保留输出、原回答不续跑 | 按不可恢复终止呈现 |
| D3 | 等待审批禁止停止 / 允许停止 | 已确认：允许停止并取消待审批、清理检查点 | 旧批准不能执行工具 |
| D4 | 仅本地协议验证 / 使用现有测试模型付费联调 | 已确认：使用现有测试模型；用户补充 DashScope compatible-mode/v1 与 qwen3.8-27b | 凭据从既有环境读取；隔离两轮、无工具、不改绑定 |

新实施任务采用默认模式，自主处理常规工程细节；用户已确认的范围不被假设替代。缺失外部凭据或状态时记录阻塞而不伪造。

## 数据与执行链

1. 会话短锁 + 短事务拒绝本会话所有活跃 Run，提交 RUNNING 和关联 USER，再登记实际句柄并发送 started。
2. 句柄保存可信归属、独立 RunCancellation 和最多 60,000 字符的脱敏正文；不积累 thinking 或原始工具参数。
3. 停止、完成、审批决定和过期共用 Run 短锁。活跃停止先 CAS/审计提交 CANCELLING，再发布停止信号；完成先获胜则重复停止返回真实终态。
4. Adapter 停止事件流、关闭后续网关准入，并等待已进入业务工具/技能/沙箱调用实际退出。严格失败先发布再释放许可，不能被 CANCELLED 掩盖。
5. 最终短事务保存 Run、部分正文消息及必要审批清理；已终态不可覆盖。等待审批停止直接取消 PENDING、版本加一、删除原状态槽并结束 Run。
6. 接受批准后同一 Run CAS 回 RUNNING，再于事务提交后登记新句柄并恢复 Runtime；已接受决定保留历史。旧片段 finally 按句柄身份释放，不能删除下一片段的句柄。
7. 前端绑定 sessionEpoch/Agent/会话/Run，POST 仅由用户点击发起，GET 查询恢复状态；CANCELLING 保留发送锁，权威终态后回读消息并开放发送。

## 事务、安全与兼容

tenant/主体来自认证上下文；必须核实 Agent→会话→Run→USER 关联和原发起人。查询不恢复、不收口。停止不绕过产物成功下载门禁或工具治理；不把中断当作回滚。

新状态复用现有字符串字段，没有新迁移。RunRepository 用可信快照 CAS；扩展 Repository 没有实现活跃查询时失败关闭，不能用有限消息页假装完整。旧 Runtime 默认不支持停止，旧 AgentRunRequest 构造器创建独立信号。整体部署新版本，不能混用不识别新枚举的旧实例。

## 失败和非目标

202 仅表示登记；CANCELLING 无结束时间。不响应中断调用可能无限等待，禁止用超时伪造终态。审计失败不发布信号，JDBC 回滚；memory 仍不提供跨仓储数据库级回滚。

缺失句柄/重启孤立运行返回 409 RUN_CONTROL_UNAVAILABLE，保留发送锁；状态竞争为 RUN_CONTROL_CONFLICT。网络失败不自动重试 POST。当前不提供跨实例命令路由、租约、重启接管、管理员代停、原 Run 续跑或强制结束。

## 验收

清单 T1～T6 与账本一致；本地协议、真实 Provider、双库和浏览器证据分别标明，不以其中一项代替另一项。实际外部调用退出等待、重复停止、审批竞争、资源隔离、同号脱敏日志、刷新和手机布局均需要实测。
