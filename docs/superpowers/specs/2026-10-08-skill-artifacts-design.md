## 背景与目标

当前沙箱的资源所有权截止于一次容器调用。Python 可以在私有 tmpfs 写文件，但接口只返回脱敏文本，容器清理后文件消失。本需求增加从容器到受控下载的完整产物链路，沿用固定版本脚本、禁网、非 root、无宿主挂载、租户授权和严格审计。

## 自主方案与边界

| 编号 | 采用方案 | 依据与影响 |
|---|---|---|
| A1 | 专用 `/workspace/output`，脚本读取固定 `CM_AGENT_ARTIFACT_DIR` 环境变量；不是模型指定的宿主路径 | 与原 16 MiB tmpfs 共用空间，不扩大容器权限；输入资源位于 /workspace/skill |

## 执行与收集

增加兼容的结构化沙箱结果/收集入口；旧 `execute(...): String` 与旧后端可返回文本且无产物，不强迫所有使用者迁移。新接口提供有界流式产物接收器或等价资源句柄，不把整批文件塞入 String/Base64 或无界 byte 数组。服务端在接收过程中统计字节、文件数与摘要。

固定引导程序需将包内脚本的 stdout/stderr 与二进制传输分离。脚本作为受控子进程运行，stdout/stderr 仍按原 32768 字节总上限收集；完成后固定程序枚举输出目录并在其自身退出前传输有界帧。只有成功退出、完整协议结束、原限额通过和清理成功，才视为该调用成功。

协议所有字段和文件字节均视作不可信输入：校验版本、长度、数量、顺序、总字节和结束标记；控制头有小固定上限，例如 8 KiB。拒绝伪造超大声明、负长度、截断、未知记录、重复路径和尾随数据。异常 stderr 与 Docker 失败分类维持现有脱敏策略。不得信任容器提供的 tenant、artifactId、storageKey、摘要或状态；摘要由服务端自行计算。

只收集输出目录下的普通文件，拒绝绝对路径、`..`、分隔符歧义、控制字符、超长路径、软/硬链接、FIFO、socket 与设备文件。目录可遍历但不作为文件产物；先约束深度及遍历项数，避免枚举资源耗尽。脚本结束后仍可能有子进程，必须停止其活动，并通过无跟随链接打开、文件描述符校验和实际读取预算抵御路径替换与文件增长，不只做一次字符串或 lstat 检查。

不得等容器退出后用 docker cp 从 tmpfs 提取，也不得通过输出内容执行 Shell、容器返回 URL、宿主路径或网络请求。LOCAL/SSH KEY/SSH PASSWORD/TLS 使用同一已固定句柄传输、清理；配置切换不重新建连或回退。

文件类型默认仅 `.docx`、`.pptx`、`.pdf`、`.txt`、`.csv`、`.json`；部署者可收紧。文件名只是显示数据，存储键由服务端生成。DOCX/PPTX 应校验 ZIP 基础结构与必要成员，PDF 校验基本格式；内容检查同样有读取/解压上限，不承诺病毒扫描或文档排版验证。HTML/SVG/脚本及宏文档默认拒绝；任何可下载文件都不在服务端执行或在线预览。

## 配置提案

下表配置尚未实施，拟归属 `cm-agent.skills.sandbox.artifacts`，具体绑定方式在 T1 复核。关闭时保留原文本行为，不进入传输与存储链路；开启但存储/密钥无效时启动校验失败，不回退为“成功但丢文件”。

| 子配置 | 拟定默认值 | 语义 |
|---|---|---|
| enabled | false | 独立产物开关；仍须 skills/sandbox 开启 |
| storage | filesystem | 首版服务端文件存储标识；不接受任意实现类 |
| root-directory | 空 | 必须显式指定受控持久卷目录，禁止静态资源、仓库、target 或宿主映射到沙箱 |
| encryption-key | 空 | 独立 32 字节 Base64 AES 主密钥，由部署 Secret 注入，不复用 JWT 或端点/模型密钥 |
| allowed-types | .docx,.pptx,.pdf,.txt,.csv,.json | 下载附件允许集合，不授予脚本执行权限 |
| max-files-per-call | 8 | 单次调用最大文件数 |
| max-file-bytes | 4194304 | 单文件 4 MiB 明文字节上限 |
| max-total-bytes-per-call | 8388608 | 单次 8 MiB 明文总上限 |
| max-total-bytes-per-run | 33554432 | 单 Run 32 MiB，审批恢复共用累计预算 |
| max-stored-bytes-per-tenant | 268435456 | 单租户 256 MiB，包括暂存、待发布与发布文件 |
| retention | 7d | 从 READY 起计时；PENDING 另用活动 Run 和创建时间管理 |
| cleanup-interval | 5m | 过期/失败/孤儿补偿扫描间隔 |
| collection-timeout | 5s | 文件传输独立有界预算，不重置原脚本预算 |

单文件、总量、Run 与租户配额均按实际读取明文字节计数；同时为加密包头/tag 的真实磁盘占用预留有界空间。部署可以调整，但必须有已验证的硬上限；拟定上限需在 T1 用内存、卷容量、浏览器 Blob 下载及原工具 30 秒超时证明可行，不凭借提高原 stdout/脚本限额实现。原执行默认 15 秒，收集最多额外 5 秒，建连、清理与治理总耗时仍需受工具超时约束。运行输入也占 /workspace 16 MiB，输出预算不保证任意脚本都拥有完整空间；满 tmpfs 需准确归类。

## 数据、存储和事务

新增领域产物与 Repository，建议业务表 `skill_artifacts`：id、tenant_id、principal_id、agent_id、run_id、run_kind、skill_id、version_id、call_id、展示文件名、media_type、size_bytes、sha256、storage_key、状态、created_at、published_at、expires_at、updated_at。状态采用 PENDING、READY、EXPIRED、DELETING、DELETED；需要失败原因时仅记录稳定脱敏码，不存载荷/路径/原异常。每个属性和每个状态有中文说明。

可信关联全部来自服务端 Run 与固定技能快照；Repository 读写含 tenant 条件，幂等键建议为 tenant + run + call + 规范化相对文件名。产物使用单独随机对象键和租户隔离目录，不使用展示文件名作为磁盘路径。相同内容可独立存储，不做跨租户去重。元数据只保存服务端计算的摘要和字节数，不保存下载令牌或公开 URL。

两库新增同版本迁移，当前最新 V18，实施时选择下一个未占用版本；所有表字段提供原生中文注释。Run/技能等引用必须明确外键或软引用与删除策略；历史文件不会因技能后续解绑或版本升级自动改归属，保留期由产物策略决定。元数据和配额预留用短事务，文件 I/O、网络和解密在事务外，不能在容器执行期间持有数据库锁。

文件落盘采用独立 AES/GCM 二进制格式、随机 IV 与完整性认证，支持版本号并以 tenant/artifactId 等可信标识做绑定；不复用为短 API Key 设计的 Base64 文本存储格式。上传到服务端的明文字节只在有界内存/当前受控暂存中存在，不进入日志、数据库或备份。写入 staging，认证完成后原子移动，元数据进入 PENDING；仅文件持久化和元数据确认均成功才返回安全产物元数据。

文件系统与 JDBC 不存在共同原子事务，必须实现幂等补偿：失败删除未发布文件、崩溃遗留 staging 扫描、文件有而元数据无的孤儿处理、元数据有而文件缺失的诊断。不可在异常时伪造 READY。并发预留与释放须跨实例有效，租户配额不能仅用 JVM 计数器；实际使用量定期核对。加密文件与元数据需共同备份，主密钥独立保管，首版不承诺在线密钥轮换。

PENDING 跨审批暂停保留但不下载；活动 Run 的临时资源设置最大遗留窗口，例如 24 小时，结合 Run 状态处理，不删除仍在有效审批中的资源。READY 按 expires_at 清理，下载先校验时效；删除采用 DELETING、短租约/防重与重试，未成功删除不释放占用配额。下载与清理采用读取租约或等效资源所有权，避免下载中途被清理；逾期/失败待清理数据不可继续下载。生产 filesystem 模式需要持久卷，多实例需要共享卷或未来扩展存储，禁止宣称单机目录支持任意分布式部署。

## 治理与公开时机

调用级链路：可信请求 → 原授权与读取预算 → 配额预留 → 容器执行/收集 → 容器清理 → 端点/技能撤销复核 → 存储与严格执行审计 → PENDING 产物元数据。

Run 级链路：模型运行/审批恢复 → 原状态检查点与运行持久化 → 成功终态 → 原严格审计成功 → READY。失败、取消、超时、拒绝、检查点失败、运行持久化失败或审计失败均不可发布；PENDING 转清理。WAITING_APPROVAL 不提前发布，恢复继续使用同一 Run 预算与幂等键。

Run 与产物终态/审计尽可能在同一数据库工作单元完成；无共同事务时通过可恢复的发布状态和前置读取判断保证“Run 未成功或审计未确认不得下载”。运行成功但发布未完成要明确可行动错误或待发布状态，不能把文件遗漏解释为没有生成。任何列表/下载同时复核 READY 与可信 Run 成功状态。

模型工具响应只携带脱敏 stdout 和有界产物摘要（opaque ID、安全名称、类型、字节数），不带二进制/Base64、宿主路径、存储键、密钥或带令牌 URL。模型不能构造 READY 或伪造可下载地址。原公开运行 DTO 尽量不变，产物列表通过独立查询接口获得。后续端点停用不销毁已发布历史文件；发布前仍执行原撤销复核。

## 下载权限与接口提案

建议接口（尚未实现）：

- `GET /api/agents/{agentId}/runs/{runId}/artifacts`：正式/会话 Run 产物列表。
- `GET /api/skills/{skillId}/trials/{runId}/artifacts`：指定 TEST Run 产物列表。
- `GET /api/skill-artifacts/{artifactId}/content`：鉴权下载。

统一要求：已认证主体；tenant 来自认证会话；产物、Run、Agent 与路径参数归属一致；principalId 为 Run 创建者；NORMAL 需 `agent:read`，TEST 需 `agent:read` 与 `skill:read`，且通过现有 TEST owner 校验。会话 Run 追加现有会话 owner 边界。不新增默认拥有跨主体读取能力的角色；若后续需要共享，应单独迭代。

缺认证 401，缺基础权限 403，跨租户/跨主体或路径归属不匹配 404；过期且已验证 owner 返回 410。PENDING/失败产物不暴露文件内容；同一调用的拒绝与失败有严格审计。缺文件、校验失败、存储不可用在响应提交前返回安全 503 及稳定 errorCode/errorId；错误码命名沿用 ApiErrorCode 约定，由 T5 添加。客户端可预期坏请求 400、配额超限 413，保持独立于原技能读取超限码。

下载不依赖静态目录、猜测路径或 URL token，禁用匿名预签名链接。响应 `Content-Disposition: attachment`，安全处理中文名称、CR/LF、双引号与双扩展名；设置受控 Content-Type、Content-Length、nosniff 与 private/no-store。首版完整下载，不实现 Range/在线预览。完整解密与摘要验证须在响应提交前完成，有界临时材料仅当前请求持有，避免 GCM 认证失败后已经发送明文。下载内容不做字符串脱敏，否则会损坏文件；安全措施是鉴权、加密、保留期和审计。

发送前完成授权、完整性验证与严格开始审计；发送后记录完成或客户端断开，不把“开始发送”记作已下载成功。响应头提交后的中断无法改写 HTTP 状态，要在日志记录同一 errorId 并终止传输，前端检查预期大小。下载日志、审计不包含文件内容、绝对存储路径、密钥或原始脚本输出。

## 控制台体验

在技能 TEST 结果、运行详情、聊天对应 assistant 回复下增加“生成文件”：名称、格式、大小、有效期、下载状态。组件按可信 runId 查询，不从模型 Markdown 提取下载 URL。无文件时区分未生成、待运行完成、已过期和收集失败；无权限不呈现他人文件名。

沿用 assets/app.js 的当前会话请求机制，实施时核实 Cookie/JWT 方式，通过鉴权 fetch 获取 Blob 后由浏览器保存；禁止把 JWT 放入 URL。支持下载错误码/errorId，失败可重试而不重跑技能；不对内容内联渲染。限制并发下载与 Blob 内存，所有导航、登出、租户切换、组件销毁撤销请求并 revokeObjectURL。刷新、其他页跳转及后退结果一致，390px 不出现横向溢出。v1 API 和已有发布/审批流程保持兼容。
