# 会话聊天页面均衡优化：需求设计

日期：2026-10-10；主题：`chat-page-ux`；修订：R0；工作模式：`mode=default`。

本轮授权为需求分析、建议和文档生成，未实施业务代码。用户明确允许对不确定事项提问，本轮 D1、D2 已问答确认；普通工程方案自主取舍并记录假设。提示词生成不等于授权执行。

## 目标与定位

面向现有管理员和开发者，让“找到会话→阅读回答→输入下一条→处理必要审批”连续顺畅。沿用 PRODUCT.md、DESIGN.md 的受控工作台，深色导航、浅色工作区、克制蓝色、中文信息架构；模式为 Operate。会话聊天负责持续对话，运行记录负责排查，两者保持独立入口。

## 决定与假设

| 编号 | 问题及候选 | 状态/选择 | 影响 |
|---|---|---|---|
| D1 | 均衡优化 / 聊天优先 / 调试治理优先 | 用户已确认均衡优化，不新增后台业务能力 | 回答为主，保留治理能力 |
| D2 | Enter 发送、Shift+Enter 换行 / Enter 换行、Ctrl/⌘+Enter 发送 | 用户已确认第一项 | 必须防中文组合输入误发 |
| A1 | 会话查找范围 | 自主假设：仅过滤当前 Agent 已加载的标题 | 不新增搜索 API，不承诺完整历史 |
| A2 | 失败输入恢复 | 自主假设：当前页内保存未确认输入，不持久存储；沿用运行中的输入锁 | 结果未知先 GET 核对，绝不自动重发 |
| A3 | 当前授权 | 根据“给出建议”与技能调用，仅分析/生成文档 | T1～T6 保持待做 |

D1/D2 来自本聊天两次结构化问题的用户答复。A1～A3 并非用户逐项确认。没有待答复决定；普通工程细节自主处理，改变已选范围时重新评估。

## 当前问题与建议优先级

| 任务 | 优先级 | 现状与建议 | 代价/风险 |
|---|---|---|---|
| T1 | P0 | 页头和说明占高、两个新会话重复；压缩页头，左侧只留一个新会话主入口，右侧扩大正文，输入稳定可达 | 中：高度/滚动容器重分配，不能遮挡审批或输入 |
| T2 | P1 | 列表无过滤；增加“查找已加载会话”、按更新时间分组、明确当前项及完整标题查看 | 低至中：最多加载 50 条，过滤不能切换会话或触发写入 |
| T3 | P0 | delta 强制滚底；改为接近底部才跟随，上翻暂停，提供“回到最新”；增加正文/代码复制与长内容排版 | 中：回读和附件异步挂载可能破坏阅读位置、文字选择 |
| T4 | P0 | 无键盘发送逻辑、发送前清空；增加 D2 快捷键、输入高度自适应、页面内未确认输入保留 | 中：IME、重复提交和结果未知分支必须测试 |
| T5 | P0 | 空审批历史占高；改为紧凑提示，非空历史可折叠；待办醒目可定位；明确停止、运行与错误状态 | 中：禁止隐藏必要待办、批准当成功、202 当已停止 |
| T6 | P0 | 手机列表在消息前且存在固定最低高度；小屏折叠列表并优先显示对话，完成键盘/响应式/共享行为回归 | 中：共享 JS/CSS 可能影响 v1 和其他页面 |

执行过程已经折叠，停止和文件下载也已存在；仅改善呈现，不重复立项实现这些能力。上述 P0 代表本轮建议优先顺序，不等于已经实施。

## 结构与交互

桌面保留全局导航、认证区；页头缩为标题及一句必要说明。左侧 Agent、唯一新会话入口、标题过滤与历史；右侧标题、真实状态、消息、必要待办和输入。小屏把会话列表收为可展开区域，默认突出当前对话；关闭后焦点回到触发入口。当前 Agent/会话始终明确。

消息保留用户/Agent 区分和段落、列表、代码层次，长代码/表格只在局部横向滚动。复制正文仅复制当前回复 TEXT 内容，不含 thinking、工具参数、审批卡或按钮；代码复制仅当前块。复制失败就近提示，不假成功，不编造服务端 errorId。保持安全 Markdown 渲染与链接协议过滤，不引入未经处理的 HTML。

初次打开会话可定位最新；上翻后 delta、执行过程、文件异步挂载及同会话终态回读不抢阅读位置。用户主动发送后跟随新轮；回到最新恢复跟随。既有 sessionEpoch、Agent/会话/Run 归属及迟到响应隔离保留。

输入默认 Enter 发送、Shift+Enter 换行，组合输入期间不提交，空白和禁用状态不发送；合理限制自动高度，输入焦点不被状态回读随意抢走。页面内保留“未确认成功发送”的原输入；网络结果未知只核对现有权威状态。已确认服务端接收的输入不得作为待重发草稿。按会话/Agent 区分，退出清理；不保存到 localStorage/sessionStorage，不承诺刷新恢复。沿用运行中的输入锁，不增加排队发送或自动续跑。

审批待办保留脱敏参数、逐项选择、汇总和显式提交，入口与数量醒目。空历史紧凑一行并可刷新；非空历史可展开且保留加载更早；读取失败始终显示具体原因，不能显示为空。消息内记录与窗口外历史的归属不改变。待审批不能像已处理历史一样被默认隐藏。

停止有明确名称与真实状态；CANCELLING 表示等待执行收口、发送仍锁定；CANCELLED 保留部分输出且提示不完整。批准已接受不等于工具成功，停止请求被接受不等于已停止。文件卡保留在所属回答，展示服务端文件名/类型/大小/有效期，沿用权限和成功下载门禁；模型说生成文件不等于存在真实产物。

## 状态验收

| 状态 | 应呈现 | 禁止 |
|---|---|---|
| 无 Agent/会话 | 原因与前置配置或首次输入引导 | 虚构资源、自动创建 |
| 加载/读取失败 | 加载占位或脱敏错误、核对入口，发送安全锁 | 失败伪装为空/就绪 |
| RUNNING | 正在生成、停止可达、可上翻读历史 | 并发发送、抢滚动 |
| WAITING_APPROVAL | 待办数量、逐项核对及提交 | 自动批准、隐藏未处理项 |
| CANCELLING | 正在停止，等待执行收口 | 202 当终态、解锁发送 |
| CANCELLED/完成 | 回读权威消息、部分/完整回答说明 | 原 Run 自动续跑 |
| 网络未知 | 核对本轮状态、上下文保留 | 自动重试发送/停止/审批 |
| 历史失败/复制失败/文件无权限 | 对应位置真实结果、已有错误编号 | 假空/假成功、越权捷径 |

## 边界、证据与限制

业务 API、数据库、权限、tenant、审计和配置不变。共享 app.js 新交互限于 v2/chatPage；公共 helper 确需改动时回归其他使用页。保留表单/操作 ID，减少重复入口时可以保留旧 ID 的兼容绑定但不保留第二个视觉主入口。

错误复用服务端脱敏原因、errorCode/errorId；如发现接口缺少字段，记录真实缺口并评估范围，不在前端伪造。未来新增失败分支按 AGENTS.md 追加适用的错误/日志/脱敏断言。

本轮实际截图与 DOM 只覆盖 1920×901 的已登录历史会话；手机、缩放、IME、运行中滚动、审批和停止未实测。CodeGraph 先调用但 app.js 符号范围不匹配当前函数，随后以直接源码复核，不用索引旧位置。未用历史通过结果作为本轮验收。
