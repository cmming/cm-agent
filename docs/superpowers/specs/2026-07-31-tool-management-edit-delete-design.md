# 工具编辑、删除与 Agent 解除关联设计

## 目标

为工具治理补齐编辑、删除和解除 Agent 关联能力，并在轻量控制台提供对应操作。删除工具前必须保护仍被 Agent 使用的工具，避免静默改变 Agent 的运行配置。

## 范围

- 新增工具完整更新接口和删除接口。
- 新增工具与 Agent 解除关联接口。
- 在控制台工具列表提供编辑、删除操作，在 Agent 详情提供解除关联操作。
- 为新增写操作补齐权限校验、严格审计、多租户隔离和自动化测试。

不包含 Agent 编辑或删除、批量解除关联、工具类型变更、Local 工具执行器热更新，以及数据库结构迁移。

## 接口设计

### 更新工具

`PUT /api/tools/{toolId}` 接收与创建工具一致的有效载荷，返回更新后的工具摘要。

- 从 JWT 主体取得 tenant 和操作人，不接受请求中的 tenant。
- 工具 ID、tenant、类型、创建人保持不变；工具类型不得通过更新接口修改。
- 可更新名称、描述、风险等级、启用状态，以及 HTTP 工具的 URL 模板、输入 Schema、参数映射、Secret 引用、超时和 MCP 发布状态。
- HTTP 工具沿用创建时全部 HTTP 安全与结构校验；Secret 仅保存引用，响应仍不返回 Secret 原文。
- LOCAL 工具不允许修改名称，避免与已注册 `ToolRegistry` 快照的名称校验失配；其他允许的元数据可更新。
- 不存在、跨租户工具返回 `404`；同租户名称冲突返回 `409`；无 `tool:write` 权限返回 `403` 并记录拒绝审计。

### 删除工具

`DELETE /api/tools/{toolId}` 在一个命令服务事务中执行。

1. 查询当前 tenant 中的 Agent 定义，筛选 `toolIds` 中包含该工具 ID 的 Agent。
2. 若存在关联，返回 `409 Conflict`，消息为“工具仍被 Agent 关联，请先解除关联后再删除”。不修改任何工具、授权或 Agent 数据。
3. 无关联时删除工具定义、HTTP 配置、MCP 发布记录和残留授权记录，再写入工具删除审计。

引用检查复用现有 `AgentDefinitionRepository.listByTenant`，在服务层过滤 `toolIds`，因此不依赖 PostgreSQL 或 MySQL 的 JSON 特有查询，也不需要迁移。

删除使用新权限 `tool:delete`。现有管理员角色增加该权限；未授权删除按现有模式记录 `ACCESS_DENIED` 审计。

### 解除 Agent 关联

`DELETE /api/tools/{toolId}/grants/{agentId}` 是现有 `POST /api/tools/{toolId}/grants` 的对称操作。

- 校验 `tool:grant` 权限，并分别确认当前 tenant 下的工具和 Agent 存在。
- 在同一事务中删除对应 `ToolGrant`，并从 Agent 的 `toolIds` 中移除工具 ID。
- 即使授权记录已不存在，也会确保 Agent 的 `toolIds` 不再含有工具 ID；返回更新后的 Agent 定义。
- 解除成功记录 `TOOL_GRANT_REVOKE` 审计；资源不存在返回 `404`，跨租户资源不可见。

## 后端实现边界

控制器仅负责路径、请求校验、JWT 主体解析、权限入口与 HTTP 响应。`ManagementCommandService` 负责更新、删除、解除关联的校验、事务和审计编排。

扩展 Repository 契约以支持：更新工具定义、删除 HTTP/MCP/授权附属记录、从 Agent 中移除工具 ID。内存实现和 JDBC 实现保持语义一致；JDBC 所有读写继续以 tenant 条件限制。

更新 HTTP 工具后，运行时每次调用都会从持久化配置读取最新 HTTP 配置。LOCAL 工具的名称限制保证现有注册快照仍可通过运行时一致性检查。工具删除后，定义查询和 MCP 目录均不再可见；残留注册快照无法绕过定义查询与治理检查。

## 控制台交互

- 工具行增加“编辑”和“删除”按钮。
- 编辑复用工具表单，加载当前摘要并回填可编辑字段；类型锁定，LOCAL 工具名称只读。提交成功后刷新工具列表。
- 删除前弹出二次确认；服务端返回 `409` 时展示“请先到 Agent 详情解除关联”。
- Agent 详情的已关联工具列表增加“解除关联”按钮，确认后调用新接口并刷新 Agent 详情与工具列表。
- 所有失败继续复用现有统一错误格式化，前端不拼接或显示 Secret。

## 测试策略

- Web 测试：覆盖更新成功、校验失败、名称冲突、无权限、跨租户不可见；覆盖删除成功、被关联时 `409`、无权限和跨租户；覆盖解除关联成功、资源不存在和无权限。
- 命令服务与 Repository 测试：覆盖更新后 HTTP 配置替换、删除的事务性附属清理、解除关联同时清理授权记录和 Agent `toolIds`，以及 PostgreSQL/MySQL JDBC 语义。
- 控制台 JavaScript 测试：覆盖编辑载荷回填和构建、删除/解除请求的 URL 与方法、冲突提示、成功后的刷新动作，以及不暴露 Secret。
- 每项新增行为先写最小失败测试，确认失败原因正确后再编写实现。

## 兼容性与风险

新增接口不会改变现有创建、查询、授权、调试和 MCP 调用路径。管理员将新增 `tool:delete` 权限；自定义角色需显式配置该权限后才能删除工具。由于删除前以 tenant 内 Agent 列表过滤引用，极大 tenant 的删除操作会随 Agent 数量线性增长，但避免了跨数据库 JSON 查询差异，符合当前持久化基线。
