# 控制台运行页界面优化设计

## 背景

`/console/v2/runs.html` 已支持流式展示模型回答，但原有页面以紧凑表单和通用详情区为主，运行入口、历史记录和实时输出之间的优先级不够直观。使用者在执行长任务时，难以快速确认当前可操作区域和输出状态。

## 目标

- 让运行入口、流式状态、历史记录与详情输出形成清晰的视觉层级。
- 强化实时输出和历史详情的可读性，同时保留现有交互标识与流式协议。
- 在窄屏设备上保持表单与内容区域可用。

## 范围

- 调整 v2 运行页的静态结构、提示文案和局部样式。
- 优化流式运行与已完成运行的详情分区：输入、输出、元数据和工具调用分别呈现。
- 更新控制台资源测试，确保页面入口和核心标识持续存在。

## 非目标

- 不修改 Agent 运行、SSE、鉴权、持久化或审计接口。
- 不增加取消运行、导出记录、筛选或新的后端数据字段。
- 不改变其他控制台页面的布局与行为。

## 方案

页面顶部增加运行工作台引导区和流式就绪状态；表单以 Agent 选择和输入编辑器分区，提供示例占位提示。左侧历史卡片强调选择态，右侧在空状态、流式状态和已完成详情之间使用一致的内容容器。

详情区域将输入和最终输出以独立文本块显示，保留原有运行元数据与工具调用。后续 Markdown 渲染仍通过纯 DOM 节点构造，不引入 HTML 注入或新的浏览器存储；详细安全边界见 [Markdown 渲染设计](2026-08-20-console-run-markdown-design.md)。

## 约束

- 保持 `runAgentSelect`、`runForm`、`runBtn`、`runList`、`runDetail` 等既有 DOM 标识不变。
- 输出不得以原始 HTML 解释；Markdown 仅能通过受限 DOM 渲染器生成安全节点。
- 样式应限定在运行页或新增类名范围内，避免影响其他 v2 页面。

## 验收标准

1. 页面初始状态清晰表达可选择 Agent、提交任务和查看历史的路径。
2. 流式输出和历史运行详情均以独立输入、输出、元数据、工具调用分区展示。
3. 现有 SSE 调用、运行详情加载和资源测试持续通过。
4. 运行页在 1100px 与 600px 以下断点仍可正常使用。
