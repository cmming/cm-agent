# Superpowers 四文档治理设计

## 1. 背景

当前 `docs/superpowers` 已按设计、计划、实现和进度保存研发过程文档，但仓库规则只说明了目录用途，没有强制每个需求完整生成四类文档，可能造成设计有记录而实施结果或验证过程缺失。

## 2. 目标

- 每个涉及新需求或仓库内容改动的独立任务都形成完整、可追溯的四文档闭环。
- 四份文档使用同一日期和主题，能够从需求追踪到计划、实际实现和验证结果。
- 区分过程记录与生产说明，避免以 `docs/superpowers` 替代 README、配置或部署文档。

## 3. 范围

- 修改仓库代码、配置、数据库、测试、控制台或文档的任务。
- 新功能、缺陷修复、重构、行为调整和工程规则变更。
- 同一任务后续修改时同步维护已有的四份文档。

## 4. 非目标

- 纯问答、解释或只读检查且未改变仓库内容的任务不生成四份文档。
- 四文档不替代生产使用说明、发布说明或 API 文档。

## 5. 文档职责

| 目录 | 职责 |
| --- | --- |
| `specs` | 说明为什么做、做什么、范围和验收标准。 |
| `plans` | 说明如何拆分、修改哪些文件以及如何验证。 |
| `implementation` | 说明最终实际做法、代码位置和方案偏差。 |
| `progress` | 记录执行状态、验证结果、遗留问题和提交信息。 |

## 6. 验收标准

- 根目录 `AGENTS.md` 明确四文档强制规则。
- 本规则自身形成同主题的四份文档。
- 四份文档命名、职责和相互引用保持一致。
