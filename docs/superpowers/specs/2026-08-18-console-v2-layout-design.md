# 控制台 v2 页面布局优化设计

## 背景

v2 控制台已完成版本化多页面拆分，但宽屏下内容会随工作区无限拉伸，能力总览的统计卡片和快捷入口层级也不够清晰。窄屏下页头与主体的空间节奏需要更稳定。

## 目标

- 为 v2 业务页面提供受控的桌面内容宽度与稳定的页头层级。
- 强化能力总览的统计信息、最近运行和快捷操作之间的视觉优先级。
- 保持原有页面地址、接口、认证方式、DOM 标识和 v1 兼容行为不变。
- 保持现有 900px 以下响应式布局，并补足小屏卡片的可读性。

## 范围

- 调整 v2 专属 `multipage.css` 的布局和交互反馈样式。
- 调整 `overview.html` 的快捷操作信息结构。
- 补充静态资源测试和本任务过程文档。

## 非目标

- 不修改 API、JavaScript 数据加载、权限、会话或审计逻辑。
- 不改变 v1 页面样式，不引入前端框架或第三方依赖。
- 不重排工具治理等复杂业务表单的字段顺序。

## 方案

1. 通过 `body[data-console-version="v2"]` 约束样式作用域，将桌面侧栏设为 256px、主体内容最大宽度设为 1480px，并让页头在桌面滚动时保持可见。
2. 为统计卡片增加顶部色带、统一高度及悬停反馈，使关键数量和状态更易扫描。
3. 将能力总览的快捷入口改为带图标、用途说明和箭头的操作卡，首个创建 Agent 操作保持主色强调。
4. 在 900px 与 600px 断点恢复非吸附页头、压缩卡片间距，避免移动端横向拥挤。

## 约束

- 动态内容继续使用既有安全文本渲染流程。
- 快捷操作仍使用原有真实链接，不能依赖客户端状态。
- 新增文字和文档均使用中文。

## 验收标准

- v2 宽屏页面内容不会无界拉伸，滚动时页头保持可用。
- 能力总览的三个快捷入口均同时呈现操作名称与用途说明。
- 小屏下统计卡和快捷操作可单列显示且不产生横向溢出。
- 控制台资源测试通过，v2 页面标识与既有脚本引用保持不变。
