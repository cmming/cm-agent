# Tool 工作区分阶段设计

## 背景

工具治理页此前将 Tool 定义、内置示例、授权和调试同时平铺。用户在查看某个 Tool 时仍需在多个面板中判断下一步，且右侧没有默认详情入口。

## 目标

- 使用左侧 Tool 列表、右侧单一工作区的布局。
- 右侧默认展示当前选中 Tool 的详情。
- 将定义、授权、调试作为按需进入的独立阶段。
- 内置 LOCAL 工具无论是否已安装均保留在左侧，按工具 ID 与已注册列表合并，每条只保留一个功能按钮。

## 范围与约束

- 仅修改控制台 v2 的静态页面和前端交互，不修改 Tool API、权限、审计或运行时注册机制。
- 已存在的内置工具提供“查看详情”，未添加的提供“添加示例工具”；模板一致性不作为是否存在的判断依据。
- 没有可选 Tool 时，右侧展示注册定义表单，保证空状态仍可完成首次创建。

## 验收标准

- 页面加载后，存在 Tool 时右侧仅显示该 Tool 详情。
- 点击编辑、授权、调用调试或注册 Tool 后，右侧只显示对应一个面板。
- 内置工具完整显示且不重复；已注册条目保留真实风险和运行时状态，未注册条目不预测执行器是否就绪。
- 选择或编辑任意普通 Tool 后，左侧已加载的内置示例不得因列表重绘而消失。
- LOCAL 工具编辑表单只读展示 MCP 发布状态；发布和取消发布通过右侧详情的独立操作完成。
