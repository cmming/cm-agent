# 控制台工具调用载荷展示优化设计

## 背景

运行详情中的工具调用原先将授权、耗时、输入摘要、输出摘要和错误信息全部放入同一个定义列表。JSON 文本难以阅读，输入输出的边界不明显，工具执行失败时也不容易快速定位错误内容。

## 目标

- 将工具调用展示为有层级的执行卡片。
- 清晰区分请求输入、执行输出、错误信息和执行元数据。
- 对可解析 JSON 自动缩进，同时保持文本内容安全、可滚动和已脱敏。

## 范围

- 调整运行详情中的工具调用 DOM 结构和局部样式。
- 在浏览器端格式化已返回的 JSON 摘要。
- 更新控制台资源测试和本组过程文档。

## 非目标

- 不改变工具调用的持久化字段、脱敏规则、权限、审计或接口响应。
- 不展示工具原始请求体、完整响应体或任何新增敏感信息。
- 不将工具输入输出作为 Markdown 或 HTML 执行。

## 方案

每个工具调用使用独立卡片：顶部展示工具名称和状态，中间展示授权状态、执行耗时与“已脱敏摘要”范围，底部并列显示请求输入和执行输出；有错误时新增醒目的跨列错误区域。

浏览器尝试以 `JSON.parse` 读取摘要，成功后使用两空格缩进重排，否则按原文本显示。两种内容均通过 `textContent` 写入 `pre` 元素，因此格式化不会改变服务端数据，也不会执行内容中的 HTML 或脚本。

## 约束

- 仅使用已经由服务端脱敏的 `inputSummary`、`outputSummary` 和 `errorMessage`。
- 输入、输出和错误内容必须保持纯文本代码展示。
- 小屏幕下元数据与载荷卡片必须自动改为单列。

## 验收标准

1. 工具调用页面能清晰显示状态、授权、耗时、请求输入、执行输出和错误。
2. JSON 摘要自动格式化，普通文本仍完整、换行安全地展示。
3. 空摘要有可理解的占位提示，错误使用单独的视觉样式。
4. 控制台脚本语法、资源测试和差异检查通过。
