# 控制台视觉与交互精修设计

## 背景

v2 控制台已完成七页拆分布局和原型对齐，但后续补充规则叠加后出现响应式优先级问题：移动端总览与会话页仍使用桌面双栏，聊天和运行页会被长历史拉成长页面，审计表格与工具操作在窄容器中缺少稳定边界。本次在保留现有信息架构、接口和权限流程的前提下，对视觉层级和操作效率做一次统一收口。

## 目标

- 让移动端总览、聊天和资源管理页面使用真正可读的单列布局。
- 让聊天、运行历史和审计表格在固定工作区内滚动，保持主要操作始终可见。
- 让资源列表在桌面端滚动时保留选择上下文，并确保工具操作按钮完整可点。
- 改善移动端导航的当前页可见性，降低小屏用户迷路成本。

## 非目标

- 不修改服务端接口、认证、权限、租户隔离、审计或数据模型。
- 不引入新的前端框架、UI 依赖或模拟数据。
- 不改变七页导航顺序、页面路径、表单字段名称和提交语义。

## 方案

- 在 `multipage.css` 末尾增加高优先级布局规则，显式覆盖后置桌面网格，恢复 900px 以下单列。
- 桌面端将资源列表、运行历史和审计表格限制在工作区高度内，列表区域独立滚动。
- 聊天页固定会话列表和消息工作区高度，将消息流、审批历史和输入区留在同一视口内。
- 工具列表操作按钮使用两列网格，避免删除等末端操作被滚动条遮切。
- `app.js` 在移动端加载页面后自动将当前导航项滚动到可视区域中央。

## 验收标准

- 1440x900 与 390x844 视口下均无页面级横向溢出。
- 总览页移动端为单列；聊天页移动端会话列表与消息区上下排列。
- 桌面端聊天页、运行页和审计页的主要操作区在首屏内可用，长内容在内部滚动。
- 工具列表中的编辑、发布、调试和删除按钮均完整显示。
- 控制台模块测试、JavaScript 语法检查和浏览器实际登录回归通过。
