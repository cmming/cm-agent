# 技能版本升级与控制台优化设计

## 背景与目标

后端支持固定技能 ID 下的版本更新，控制台只有创建入口；同名 ZIP 被创建接口拒绝，用户无法完成升级。页面版本字段与真实响应不一致，显示 v—。

## 方案与约束

沿用中文受控工作台，以“列表—详情—操作”为基础。列表栏用原生 details 收纳“导入新技能”；当前详情用原生 details 提供“上传新版本”，明确 SKILL.md 的 name 不可修改，上传只生成候选。已有候选的替换提示旧 TEST 不能用于新候选发布。

上传以当前详情双指针作为 CAS 预期值，不发送旧兼容单指针；服务端继续承担授权、租户、审计和不可变版本。只读主体不展示升级，提交前复核权限；页级上传锁拒绝重复。迟到响应不覆盖新选择或新会话。失败保留文件，冲突提示人工刷新，网络错误先确认结果，不自动重放。

版本号取 versionNo；通过历史响应把候选/正式指针映射为 vN；历史使用中文发布状态并折叠。缩窄列表、压低辅助内容、改善局部对比度与焦点，窄屏改单列。

## 非目标与验收

不修改后端 API、沙箱隔离、数据库、部署或真实凭据；不自动完成 TEST、发布、回滚。验收对应 T1～T6；自动化通过、界面状态真实；原生文件上传与真实服务升级未通过时必须如实记录外部限制。

## R1：导航一致性补充设计

保留 R0 设计与验收历史。当前采用范围追加 T7～T9，修复跨页导航缺失沙箱页签、再次进入组件挂载失效。共享导航不执行目标 HTML 的脚本和 head 内容，因此沿用现有预载策略，在全部 v2 入口预载沙箱依赖。

在目标页面已读取、校验且仍为最新导航后，先释放技能和沙箱组件，再替换 body；返回技能页创建新组件。失败或过期导航不释放当前页面。退出登录也释放组件。沙箱组件释放时清空未提交材料，废弃列表请求；保存成功、失败和 finally 分支均拒绝更新后续页面。

统一 app.js 2.0.28、sandbox-endpoints.js 1.1.1 缓存引用。进入技能页默认选中“技能与发布”，与刷新保持一致；不保存临时选择、页签或未提交文件。真实 localhost:8080 只读导航验收比较页签、列表、默认详情和导入入口，并验证重入后的事件绑定。
