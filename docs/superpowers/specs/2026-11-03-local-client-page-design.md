## 背景与目标

`local-client.html` 解决 Server 与浏览器所在电脑不同机时的设备连接管理问题。用户先在目标电脑运行本地客户端 `pair` 命令，再把终端输出的签名配对包粘贴到浏览器页面。页面确认后，设备才能被当前账号选择并用于后续 Run。

页面目标是让设备身份、绑定主体、平台、状态和撤销入口清晰可见，同时把“页面管理设备”和“客户端执行操作”分开。页面不执行本机文件、网络或命令，也不提供虚假的在线状态。

本组 R0 是按页面重组后的基线，不代表功能未实施；R1 在 2026-11-04 补全授权模式、RBAC、配对落盘生命周期、设备管理细节和系统状态边界。

## 页面结构与流程

1. 打开页面，读取当前账号设备列表。
2. 用户在目标电脑运行客户端 `pair`，复制 JSON 配对包。
3. 页面解析请求 ID、设备名、平台、公钥、nonce 和签名；输入变化时刷新预览。
4. 用户提交配对包，服务端校验签名和身份，创建待确认配对。
5. 页面确认配对，服务端绑定当前认证主体和 tenant，设备出现在列表。
6. 用户选择设备查看详情或撤销；执行能力由聊天页选择设备和 Run 授权模式后派发。

### 配对最终落盘

浏览器确认只让服务端生成已配对设备，客户端仍需轮询配对状态并保存设备标识。若客户端已退出、轮询超时或本机身份落盘失败，服务端记录可能已存在，但本机客户端尚未完成配对。页面和服务端提示必须区分“服务端已确认”与“客户端已完成”，不能仅凭浏览器确认宣称设备可用。

## 数据与信任边界

- 配对包是客户端生成并签名的设备身份材料，不是服务端授予权限的凭证。
- 浏览器只是转交者和确认触发者；浏览器脚本不能生成有效设备签名。
- 服务端必须验证签名、nonce、requestId、过期时间、设备公钥、租户和原主体，并防止重放。
- 设备列表不推断在线状态；实际可用性在挑战、领取和执行时判断。
- 撤销必须阻止新挑战和新的派发；已经进入派发的操作可能结果未知，不能自动重放。

## RBAC 与密钥存储

| 操作 | 最低权限 |
|---|---|
| 登记配对包 | `agent:run` |
| 确认配对 | `agent:run` |
| 读取设备列表 | `agent:read` |
| 撤销设备 | `agent:run` |

配对包不是权限凭证。服务端仍校验 tenant、原主体、设备签名、nonce、requestId、过期时间和重放。设备私钥只保存在用户电脑：优先使用系统密钥链；不可用时必须以本地口令保护，不能静默降级为明文。

## 授权模式

| 页面名称 | 代号 | 设备客户端作用域 |
|---|---|---|
| 操作前询问 | `ASK_ON_EFFECT` | 文件、网络、命令和未知外部副作用逐项确认 |
| 帮我批准 / 高风险时询问 | `ASK_ON_RISK` | 可信低风险操作自动，高风险和未知操作确认 |
| 完全访问 | `FULL_ACCESS` | 当前 Run 内，在用户账号权限、设备身份、租户、工具 grant 和审计约束下自动执行 |

模式由聊天页随 Run 提交，不在本页选择。这里的 `FULL_ACCESS` 是设备账号范围，不等于项目内固定 `project_*` 工具授权；项目组边界见[本地项目页设计](2026-11-03-projects-page-design.md)。

## 授权与执行边界

聊天页可以为当前 Run 选择已配对设备、授权模式和操作类别。授权只对当前 tenant、主体、Agent、会话、Run 和设备有效。文件、网络和命令在用户电脑执行，命令继承用户账号权限，可能访问项目外资源和网络，停止不等于回滚。`FULL_ACCESS` 在这里表示设备账号可访问范围，不等于项目内 `project_*` 工具授权。

## 页面状态

| 状态 | 页面行为 |
|---|---|
| 无设备 | 显示配对说明和空态，不显示虚构设备 |
| 配对包无效 | 显示可行动中文错误，不提交 |
| 配对待确认 | 显示设备名称和平台，限制重复提交 |
| 已配对 | 显示在设备列表，可查看详情和撤销 |
| 撤销/不存在 | 显示服务端权威结果，不自动重建设备 |
| 网络失败 | 保留用户输入，提示稍后核对，不声称设备可用 |

### 设备列表与详情

- 列表显示服务端返回的活跃和已撤销设备，状态分别显示“已配对”和“已撤销”。
- 设备数量当前按列表总数计算，不宣称等同活跃设备数。
- 详情显示平台、设备标识、配对时间、状态版本和最近更新时间。
- 撤销需要二次点击；请求携带页面读取的状态版本，版本冲突时刷新详情后再决定。
- 顶部“系统运行正常”只表示控制台/服务端健康，不代表任何设备在线；设备在线状态不在本页显示。

## 非目标

- 不在页面执行文件、网络或命令。
- 不实现桌面 GUI 自动化。
- 不显示或推断设备在线状态。
- 不接受手工伪造的设备 ID、公钥或授权结论。
- 不把 Windows 单平台通过写成 macOS/Linux 已验收。

## 验收标准

配对包解析、预览、提交、确认、客户端最终落盘、列表、详情、二次撤销和错误提示可用；跨账号设备不可见；RBAC 和密钥存储符合要求；设备身份和配对证明不可伪造；页面明确风险；桌面与窄屏不遮挡主要操作；远程 TLS、多实例和三平台限制有清晰记录。

### 打包方案

`cm-agent-local-client` 使用 Maven Shade Plugin 3.6.0，在 `package` 阶段附加 `cm-agent-local-client-<版本>-all.jar`。该产物写入 `Main-Class: com.cmagent.localclient.LocalClientApplication`，合并运行时依赖并使用服务资源转换器保留 `META-INF/services`。

普通主 JAR 继续保留，不写主类，也不写入依赖归并结果。这样，后续若其他模块把客户端模块作为普通依赖，不会意外获得重复的 core、Jackson 或 JNA 类。Shade 过程移除依赖原始 `META-INF/*.SF`、`*.DSA` 和 `*.RSA` 签名，因为依赖签名在合并后已失效，保留会导致 JVM 拒绝加载。

构建电脑需要 JDK 21 和 Maven 3.9+，执行：

```powershell
mvn -pl cm-agent-local-client -am -DskipTests package
```

目标电脑只需要 JDK 21 和 fat JAR。配对与启动命令统一为：

```powershell
java -jar cm-agent-local-client-0.1.0-SNAPSHOT-all.jar pair --server https://服务端地址 --name 设备名称
java -jar cm-agent-local-client-0.1.0-SNAPSHOT-all.jar run
```

版本号变化时以实际构建输出替换示例文件名。原生安装包、代码签名、自动升级、真实远程 TLS 和跨平台实机仍不在本次范围内，继续由 T9/T17 跟踪。
