# 文档组织整理：设计

日期：2026-11-13；主题：`doc-organization-followup`；修订：R1；模式：`mode=default`。

## 背景与目标

此前只读审查发现生产说明对本地项目非回环条件表述冲突，配置表被正文截断，运维步骤与历史状态混杂；架构和部署重复列出迁移分组，历史主题追溯及 Git 状态维护有成本。用户要求按建议逐步修复。

## 决定与范围

- T0–T1：以当前请求边界和配置为证据，说明默认回环、显式非回环条件、请求头检查和窗口所在机器；完整保留部署安全限制。
- T2：保留历史结果，标注只适用于当时环境，按实际主题链接项目页和设备项目账本；不推断当前部署或提交状态。
- T3：部署指南作为迁移分组入口，架构说明保留 Flyway 职责和方言选择，链接部署指南。
- T4：用索引关联真实主题，保留全部历史路径和原文。保留已有 Git 信息作为日期化历史快照，后续实际状态由 Git 查询；新增主题时维护结构索引。
- T5：独立实施工作包采用六份 R0，状态与证据集中于账本。

假设：既有历史记录是形成时证据，不证明当前环境；不确定的跨主题关系不标为替代。非目标：修改业务代码、安全配置、历史业务状态、数据库、运行服务，或将历史文件移动、删除、物理合并。不可用证据可在原账本定点补充可用性说明，保留形成时路径。
