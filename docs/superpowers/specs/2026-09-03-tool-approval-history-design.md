# 会话审批历史回显设计

日期：2026-09-03。主题：`tool-approval-history`。

关联：[任务计划](../plans/2026-09-03-tool-approval-history.md)、[实现说明](../implementation/2026-09-03-tool-approval-history-implementation-design.md)、[进度账本](../progress/2026-09-03-tool-approval-history-ledger.md)。

## 背景与目标

原人工确认页面主要读取 PENDING，已处理审批仅在当前执行过程临时保留，刷新后无法完整回显。用户已确认补齐持久历史：同一会话的多次审批不互相覆盖，支持刷新、重新进入、查看更早记录；保留原审批提交协议。

## 产品规则

- 待审批操作仍在独立交互区，只有服务端认可的发起人及权限可以提交；历史始终只读，不出现再次允许或拒绝按钮。
- 历史按 Run 关联到消息下方，折叠显示。相同 Run 可以有多个 approvalId，每轮及每项允许/拒绝分别保留。对应消息不在最近消息窗口时，记录放在审批历史区，不能丢弃。
- 展示状态、决定时间、发起人/审批人名称、运行编号、审批编号、工具及调用标识、已脱敏参数、逐项决定。明确“审批允许不等于工具执行成功”。
- 默认取最新 20 条，按决定时间和审批标识倒序查询；同一 Run 内按时间正序展示，可继续加载更早记录、刷新首屏。刷新回到最新页，不保证并发写入时的事务快照。
- 历史查询失败要保留已有记录及分页游标，展示可重试原因和错误编号，不能伪装成空记录。旧会话/旧登录响应不得污染新会话。

## 后端合同与安全约束

新增 GET `/api/agents/{agentId}/conversations/{conversationId}/approvals/history`，参数 `limit` 默认 20、范围 1～100，`cursor` 使用上页返回值。响应为 `{items, nextCursor}`，明细沿用安全审批视图。

权限为 `agent:read`，无需 `agent:approve`；仍必须通过可信 tenant、Agent、会话归属校验。仅返回 APPROVED、PARTIALLY_APPROVED、DENIED、EXPIRED、CANCELLED，不返回检查点、参数哈希或真实密钥。游标只定位数据，不能作为授权证明，损坏或跨会话游标返回 400。

复用现有审批表和明细表，不新增迁移；JDBC 为跨服务重启历史的持久化前提。memory 模式只在进程内有效。GET 不修改过期状态、不恢复 Run、不执行工具。

## 非目标

不增加全局审批中心、他人代批、永久允许、定时过期清理、自动重试、完整消息分页、运行结果与批准结果混为一体或新数据库框架。

## 验收标准

1. 多个 Run、同一 Run 多轮审批、混合决定可完整回读；刷新后仍在。
2. 相同决定时间按审批标识稳定分页，无重复遗漏；其他 tenant/Agent/会话不能读取。
3. 待审批与历史分离，历史全只读，查询不会触发执行。
4. 前端覆盖会话切换竞态、分页失败重试、纯文本安全展示、消息关联及未关联兜底。
5. JDK 21 后端定向测试、前端测试、Rocky PostgreSQL 16/MySQL 8.4 集成测试通过；实际验证边界在账本记录。
