# 错误诊断开发规范设计

## 背景

系统出现失败时，如果前端只显示统一错误、后台日志缺少关联编号或异常被直接吞掉，维护人员无法快速判断是参数、权限、依赖、网络还是程序异常。项目需要一套对后续需求均生效的强制开发规范。

## 目标

- 前端展示可行动、经过脱敏的正确错误原因。
- 前端错误编号能够直接关联后台日志。
- 后台日志包含足够且可信的诊断上下文。
- 未预期异常保留后台堆栈，同时不泄露敏感信息。
- 通过测试防止统一错误文案、缺失日志和日志泄密回归。

## 范围

- API、Service、运行时、外部依赖调用和控制台的错误处理。
- 错误码、错误编号、HTTP 状态、日志级别、日志字段、异常堆栈、脱敏、审计边界和测试要求。
- 后续所有新增或修改的失败分支。

## 非目标

- 本任务不修改运行时代码、错误响应 DTO、日志框架或日志采集平台。
- 不规定某一个商业可观测平台或分布式追踪产品。
- 不把安全审计与技术错误日志合并。

## 方案

在仓库根 `AGENTS.md` 新增“错误诊断、日志与前端提示规范”，明确：

1. 使用 `requestId`、`traceId`、`runId`、`toolCallId` 或随机 `errorId` 建立关联。
2. 前端显示脱敏原因、稳定 `errorCode` 和需要定位时的 `errorId`。
3. 后台日志记录错误编号、操作、错误码、可信 tenant、资源、状态、耗时和异常类型。
4. 未预期异常只在最终处理边界记录一次脱敏堆栈。
5. 区分 `ERROR`、`WARN`、`INFO`，避免正常校验滥用错误日志。
6. 区分技术日志和严格审计，禁止互相替代。
7. 强制测试前端原因、错误码、错误编号关联、日志存在性和敏感信息不泄露。

## 约束

- 错误上下文只能来自认证主体、服务端状态或已校验对象。
- 不允许记录请求原文、凭据、模型输入输出或未经清理的外部响应。
- 未知内部异常不得向前端暴露堆栈和实现细节。
- 同一异常只在最接近最终处理的边界记录一次堆栈。

## 验收标准

- `AGENTS.md` 明确前端错误信息、错误码和错误编号要求。
- `AGENTS.md` 明确后台日志必需字段、级别和堆栈策略。
- `AGENTS.md` 明确日志脱敏、审计边界和测试要求。
- 规范能够形成“前端错误编号 → 后台日志 → 具体原因”的排查路径。
