# 本地项目页布局优化设计

日期：2026-11-20；主题：`projects-layout-refresh`；修订：R0；模式：`mode=default`。

## 背景与目标

现有本地项目页已经具备项目来源、列表、详情、会话、文件和审批能力，但顶部说明、来源切换和主工作区连续堆叠，宽屏空状态占用过大，列表名称容易被压缩，详情区的项目身份与工作视图也缺少明确分界。本轮目标是在不改变业务语义的前提下，让主要任务路径更清楚、页面密度更稳定、窄屏顺序更自然。

## 非目标

- 不替换现有“受控工作台”视觉系统，不引入新字体、图标库或装饰性渐变。
- 不改变业务文案、接口、权限、认证、租户、审计、审批和本地文件能力。
- 不调整其他控制台页面的信息架构，仅同步共享样式缓存版本。
- 不把当前远端页面注入式视觉检查表述为部署验收。

## 当前事实与假设

- 页面是 Operate 场景，核心对象是“当前项目”，主任务是选择项目后进入会话或文件工作区。
- 页面结构由 `projects.html`、`local-projects.js`、`client-projects.js` 和共享样式共同驱动；本轮没有确定需要修改 JS 行为的证据。
- 用户要求“美化布局”，没有指定新的品牌方向；按现有 DESIGN.md 做结构细化，而不是视觉世界替换。
- 工作树已有大量修改，目标文件也处于修改状态；本轮只增量写入相关内容。

## 决定

| 编号 | 决定 | 原因与影响 |
|---|---|---|
| D1 | 采用“页面标题 → 环境与来源控制带 → 项目列表/当前项目工作区”的阅读顺序 | 先说明运行环境和来源，再进入对象选择；减少孤立控件 |
| D2 | 桌面项目列表固定为约 300px，详情区占据剩余宽度 | 保留列表上下文，提高长项目名的可读性；中间宽度降到 250px |
| D3 | 项目详情拆出身份头、标签式工作视图和当前任务内容 | 让当前项目、会话/文件和任务区形成稳定层次，不改控件语义 |
| D4 | 空状态、文件搜索和项目身份共用相同表面、边界和间距节奏 | 避免页面在空态、会话态和文件态之间明显跳变 |
| D5 | 760px 以下显式切换单列，项目来源按钮铺满可用宽度 | 保证 390px 宽度下无水平溢出，DOM 顺序与视觉顺序一致 |
| D6 | 共享样式版本提升为 `1.9.0`，所有 v2 入口同步引用 | 避免部署后浏览器继续使用旧样式 |

## 验收标准

- 首屏可快速识别页面标题、主操作、运行说明、项目来源、项目列表和详情区。
- 桌面、1024px 和 390px 宽度均无页面级水平溢出，窄屏列表与详情顺序为单列。
- 已选项目的名称、元数据、项目管理和“会话/文件”视图关系清楚，控件仍可键盘访问。
- 空状态、会话和文件视图保持同一视觉语言，不引入嵌套卡片或重阴影。
- 现有业务脚本测试和 `cm-agent-console` 模块测试通过；布局检测无遗留。

## 假设

- 当前登录后的真实项目数据足以代表常规列表、空状态、会话和文件视图检查。
- 本次不使用新增图片或外部资源；项目图标继续复用现有内联 SVG。
- 远端部署、浏览器缓存失效和最终发布验收由后续发布任务完成。
