# docs 全量整理：设计

日期：2026-11-13；主题：`docs-full-review`；修订：R1；模式：`mode=interactive`。

## 需求与已确认决定

用户选择“全面处理：逐份检查职责、内容和链接，并逐组核定归档；证据不足明确记录”，并补充“历史文档也包含”。沿用此前已确认的稳定路径、固定文档职责、两类权威来源、责任结束归档及带日期纠错规则。

范围为开始时 docs 的全部 543 份 Markdown，以及本次新增六份工作包；开始时有 115 个历史主题。记录结构和引用覆盖与逐组责任核定，不能把静态检查冒充所有业务语义或运行环境重新验收。

## 方案

- T0–T1：记录摘要，逐份读取并按职责解析结构、标题、引用、代码块和内容候选；以组为单位检查设计/验收与账本的关系。
- T2：当前说明对照相关源码和已确认要求；历史原意保留，重要纠错另加日期与依据。
- T3：人工核对账本中的最新范围、已完成事项与未关闭验收；不能按关键字、日期或提交自动归档。分析文档完成与后续业务待做分别描述，只有原包明确限定文档范围时才按该范围核定。
- T4：原账本追加本次核定；无账本主题只在本次覆盖记录中说明不足，保留原集合；目录提供原账本的导航投影。本包保存全量覆盖快照。
- T5：本地链接与锚点、目录分组、原文前缀、范围外摘要和 Git 状态一起核对。

## R1 差异与证据准则

用户明确追加 Git 补证范围：原 16 个归档状态待核实主题。继续保留原路径、未提交修改，以及不提交、推送、部署或重跑历史测试的边界。

| 差异 | 类型 | 调整与理由 | 任务 |
|---|---|---|---|
| D6 | 新增 | 原 R0 只按现有文档核定；R1 增加本地可达 Git 提交、路径重命名、同一失败用例的修复与验证记录 | T6 |
| D7 | 澄清 | 合并、代码和测试存在不等于通过；采纳提交须在 HEAD 历史中，非祖先分支材料只作线索 | T7 |
| D8 | 澄清 | 没有同日账本时查找明确引用原设计/计划的共同账本；仍无旧账本的新核定写本次账本，不能补造当时测试结果 | T8 |
| D9 | 调整 | 原 R0 分类和覆盖保留快照；当前分类按 R1 Git 补证更新，范围未查明则继续待核实 | T8–T9 |

本轮任务编号 T6–T9。设计形成或纯路径整理的完成只归档该文档责任，不扩大到业务实现验收；仍有明确原验收未执行的改为待续。缺少真实命令结果或明确取消/移交依据的保持待核实。

## 边界

不迁移或删除历史文件，不替原包完成业务待办，不为满足分类而补造取消或移交记录。相近主题及后来实现不能自动关闭原包验收缺口。出现本轮无法证实的跨文档承接关系时记录待核实。
