# 本地项目页字阶与会话态收敛设计

日期：2026-11-20；主题：`projects-typeset-refresh`；修订：R2；模式：`mode=default`。

## 背景与目标

本地项目页的基本布局已经按“标题、环境来源、列表/详情”重组，但真实会话状态仍暴露两个问题：字体角色混杂，按钮和标题比说明文字更大；会话内容按输入表单、消息、操作历史的顺序堆叠，导致长表单先把消息推到首屏之外。本轮目标是建立稳定的产品字阶，并让会话状态在真实数据下可直接阅读和操作。

## 非目标

- 不改变认证、权限、项目隔离、审批、命令、运行轮询和消息接口。
- 不替换现有字体家族、品牌色或图标系统。
- 不调整其他控制台页面的整体布局。
- 不把注入式真实页面截图描述为远端部署验收。

## 当前事实与假设

- 页面使用 `Segoe UI` 与 `Microsoft YaHei` 回退，适合 Windows 管理场景。
- 会话真实状态包含长会话标题、多条消息、空运行状态、空审批、授权方式、两段安全和同步等待说明。
- 现有 `project-development.js` 通过固定元素 ID 更新状态、消息和表单；调整 DOM 顺序不会改变这些挂载点。
- 当前页面尚未部署到远端，视觉检查只能在登录页面注入最终静态资源与等价 DOM 结构。

## 决定

| 编号 | 决定 | 影响 |
|---|---|---|
| D1 | 产品字阶固定为 30/24/16/14/13/12px 六个角色，并保留 21px 窄屏对象标题 | `DESIGN.md` 与本地项目页共同采用；标题、正文、控件和元数据有稳定层级 |
| D2 | 中文标题字距收敛到 `-0.02em` 以内，正文使用平衡/自然换行 | 避免西文式过度紧排，长标题在窄屏自然换行 |
| D3 | 会话顺序改为会话头、运行/审批状态、消息、输入区、运行操作 | 消息优先进入视野；输入区仍有清晰边界 |
| D4 | 消息记录作为独立滚动区域，用户消息右对齐、Agent 消息左对齐 | 长会话仍可扫描，消息角色清楚 |
| D5 | 授权说明仅在 1200px 以上使用左右两列，1024px 与窄屏均使用单列 | 降低宽屏表单高度，避免中间宽度把说明压成窄竖条 |
| D6 | 最近会话使用单行省略列表；共享样式版本提升为 `1.10.0` | 避免长标题撑高列表，并让部署后获取新样式 |

## R1 文件面板结构修复

用户部署 R0 后反馈文件区域出现“乱码”。只读遍历当前账号 5 个项目、19 个会话和 52 条消息，未发现 `U+FFFD` 或常见 UTF-8 误解码字符；真实问题是文件面板被浏览器解析到 `<main>`，显示在详情面板之外。

| 编号 | 问题与决定 | 影响 |
|---|---|---|
| D7 | 删除会话区与文件区之间多余的 `</div>`，使文件面板继续位于 `projectWorkingGrid` 内 | 文件标题、搜索、目录和预览重新出现在项目详情面板中 |
| D8 | 增加块级容器栈回归断言，并用浏览器解析本地 HTML 验证父子关系 | 类似标签错位会在测试阶段失败，不再依赖浏览器自动修复后的人工目测 |

## R2 左侧项目与会话导航

用户要求把项目会话放在左侧项目下面。当前右栏同时承担历史列表和当前会话，切换对象需要跨区域移动。R2 将历史列表转为项目下的二级导航，右栏只显示当前任务。

| 编号 | 决定 | 影响 |
|---|---|---|
| D9 | 左侧导航分为项目段和项目会话段，桌面宽度约 320px | 项目、会话、当前内容形成清楚的导航与详情关系 |
| D10 | 会话列表常驻；当前会话使用蓝底、蓝边和状态点；新建会话入口折叠在列表下方 | 会话优先可扫描，低频创建动作不挤占导航空间 |
| D11 | 右栏移除重复会话列表；点击左侧会话时自动切回会话视图并隐藏未选择空态 | 对象切换仍沿用既有消息、审批和文件逻辑 |

## 验收标准

- 页面标题、当前项目标题、分区标题、正文、控件标签和元数据无需阅读内容即可区分。
- 真实会话首先看到会话标题和状态，随后是审批与消息；输入区位于消息之后。
- 用户与 Agent 消息左右分列，长文本可换行，消息区域独立滚动。
- 390px 下会话、消息和授权表单无水平溢出，输入控件和主操作保持可用。
- Node、Maven、type/layout 检测通过；部署后最终发布背景由后续任务记录。
