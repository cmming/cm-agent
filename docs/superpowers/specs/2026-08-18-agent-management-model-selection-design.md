# Agent 管理编辑、删除与模型选择设计

关联计划：[实施计划](../plans/2026-08-18-agent-management-model-selection.md)。

## 背景与目标

现有 Agent 管理页只能创建 Agent，模型名称由用户自由输入，服务端固定绑定默认模型配置。这会导致模型名称与凭据、Provider、端点脱节，也无法在管理端修正或删除未使用的 Agent。

本次目标是在不改变既有数据库结构的前提下：

- 支持 Agent 创建、编辑和删除；
- 让 v2 控制台从当前租户模型配置中选择模型；
- 由服务端校验所选配置属于当前租户且处于启用状态，并从配置读取模型名称；
- 以权限、租户隔离、严格审计和历史保留约束所有写操作。

## 范围与非目标

范围包括 `/api/agents` 的创建、更新、删除接口，内存/JDBC 仓储实现，v2 Agent 页面、测试和发布文档。

不新增数据库迁移，不删除会话、运行、审计或工具调用历史，不增加批量删除、模型凭据回显或跨租户引用能力。v1 仅保留受限兼容：旧 `modelName` 必须在当前租户唯一匹配一个已启用模型配置。

## 方案与约束

`POST` 和 `PUT` 使用 `modelConfigId`。命令服务在事务中读取模型配置，拒绝不存在或停用配置，并把配置 ID 与受控 `modelName` 写回 Agent。更新保留创建人、温度、最大迭代数和工具关联，防止管理表单覆盖授权关系。

`DELETE` 需要 `agent:delete`。删除前检查会话或运行历史；存在历史返回 `409`，调用方应停用 Agent。无历史时删除其工具授权和 Agent，并与审计写入处于同一事务。所有仓储查询均以认证主体 tenant 为边界。

## 验收标准

- v2 页面模型字段为已启用模型配置下拉框，并提供编辑、取消编辑和删除确认；
- `PUT` 能更新名称、提示词、启用状态和模型绑定；
- `DELETE` 能删除无历史 Agent，已有历史返回明确 `409`；
- 创建、更新、删除分别写入 `AGENT_CREATE`、`AGENT_UPDATE`、`AGENT_DELETE` 审计；
- 禁用、跨租户或不存在的模型配置不能被绑定。
