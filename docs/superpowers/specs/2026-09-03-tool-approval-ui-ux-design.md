## 背景与目标

现有聊天页收到 `approval-required` 后展示请求级卡片，锁定当前会话发送；用户逐项选择决定并整体提交，收到 `approval-decision` 后继续展示执行过程。失败时查询权威状态，不自动重放决定。

主要交互问题是批量按钮名称容易被误解为立即批准、缺少选择汇总、提交与恢复反馈相似、只读提示误断言为缺少权限、审批终态继续占据大量空间，以及重绘时选择/焦点容易丢失。

本次目标是让用户明确知道“当前在确认什么、选择了什么、点击后有什么结果、是否已经被服务端接受”，不扩大授权范围。

## 范围与非目标

- 仅修改 `cm-agent-console` 的共享脚本、样式、v2 资源版本及相关测试和文档。
- 不变更 REST/SSE 字段、审批权限、状态持久化、租户边界、数据库迁移或功能开关。
- 不新增前端框架、永久允许、自动批准、原始参数编辑、独立审批中心或主动过期扫描。
- 本轮未补完整审批历史回显。当前查询只加载 PENDING，并临时保留刚处理请求；多轮和刷新后的终态历史需要后续后端历史查询与前端时间线支持，不能用内存草稿替代。
- 不引入本地存储草稿；不通过浏览器时间推断权威 EXPIRED 状态。

## 交互合同

1. 无默认允许。参数区域默认展开，说明“已脱敏、不可编辑、仅授权本次具体调用”。
2. 单项只保留逐项选择与明确提交按钮。多项保留“全部选为允许”“全部选为拒绝”，并说明仅选择、不提交。
3. 显示“已选择 X/Y 项、允许 A 项、拒绝 B 项”；未全部选择时禁止提交。全允许按钮说明继续执行，全拒绝说明结束，混合决定按钮直接显示数量。
4. `SUBMITTING`、`RESUMING`、`CHECKING`、`UNKNOWN` 为前端阶段，不替代服务端审批状态。批准不表述为工具成功。
5. 终态调用详情默认折叠，保留决定和时间。只读说明同时涵盖原发起人、权限和有效期，不能仅凭 `canDecide=false` 断言具体拒绝原因。
6. 错误就近显示在对应卡片，并保留服务端错误码/编号；404 已移除卡片时在会话区域显示。增加“刷新审批状态”按钮，只执行查询，不重放决定。
7. 状态查询失败保持只读和发送锁；重新查询得到可决定的服务端状态后才允许继续操作。
8. 当前页面内存草稿只回填同一审批版本及调用快照。Agent、会话、版本、工具 ID、调用 ID、明细或参数摘要改变时失效；退出、切换 Agent 或审批接受后清理相应草稿。
9. 重绘保留当前卡片内的键盘焦点；控件禁用时转交该卡片状态节点。不主动抢占其他区域焦点。

## 安全与兼容性约束

工具参数继续通过纯文本展示，既不渲染 HTML/Markdown，也不解析再序列化 JSON，避免金额或大整数显示精度变化。客户端提交仍仅包含 `expectedVersion` 与明细 `itemId/decision`；草稿和汇总均不能替代后端校验。

保持后端既有限制：无主动过期清理、无崩溃自动接管，当前会话发送锁不是跨客户端执行租约。此次 UI 优化不承诺解决这些后端问题。

## 验收标准

- 单项、多项、混合决定、空/非法/重复决定的汇总与提交文案正确。
- 实际异步编排双击只发一次 POST；接受后恢复失败保留错误码/编号，不自动重试。
- 网络与查询同时失败时保持不可提交；手动刷新仅查询，旧登录会话返回不覆盖新页面状态。
- 草稿防御性复制，版本/调用/权限变化失效，不进入浏览器持久化存储。
- v2 所有入口引用一致的新脚本/CSS 版本，资源合同与打包通过。
- 浏览器 DOM、焦点和窄屏视觉验收单独标注；静态断言和隔离编排测试不能冒充真实浏览器验收。
