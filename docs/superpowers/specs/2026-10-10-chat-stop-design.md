# 会话问答停止本轮：需求设计

- 日期：2026-10-10；主题：`chat-stop`；修订：R0；工作模式：`mode=interactive`。
- Git 基线：`8cd22b3f031c5887cba86d1ba3f4222d9a057184`；当前是需求设计，业务未实施；未提交。

## 背景与决定

聊天支持持久化会话、实时回答、工具进度和人工审批。浏览器断开只停止事件投递，后台仍继续执行；目前用户无法显式结束当前运行。用户希望在回答不合预期或不再需要时主动停止，并继续对话。

| 决定 | 问题及选项 | 用户选择 | 状态及影响 |
|---|---|---|---|
| D1 | 控制台聊天 / 需求工作包讨论 | 控制台聊天 | 已确认；改动定位到会话运行链 |
| D2 | 停止本轮并保留输出 / 暂停并恢复原执行 | 停止本轮并保留输出 | 已确认；无原 Run 继续入口，新消息创建新 Run |
| D3 | 等待审批也允许停止 / 只允许执行中停止 | 等待审批也允许停止 | 已确认；需撤销待审批、清理检查点，阻止旧批准恢复 |

用户允许对未确定事项进行询问，本工作包采用交互模式。常规实现细节按当前代码约定处理。A1～A5 为分析时选择的实施假设，详见清单；它们没有被写成用户已确认的决定。后续实质改变部署范围、停止语义或数据保留方式时继续逐项询问。

## 范围与非目标

首版支持 v2 会话聊天正在生成、模型等待、工具/技能执行、审批恢复执行及等待审批阶段的停止。运行记录与审批历史识别新增停止状态；共享代码须兼容 v1 和既有单轮 API。保留已输出的脱敏回答和已经发生的受治理调用记录；刷新后能回看，停止收口后能继续发新消息。

不提供暂停后续跑、重放原 Run、重新生成、撤销已发生的外部副作用、管理员代停、批量取消、独立技能 TEST/调试页入口或跨实例执行接管。现有自然断线、会话切换和退出登录不自动触发业务停止。

## 当前调用链

`chat.html → assets/app.js/sendChatMessage → console-core.js/stream → ConversationController.stream → ConversationService.send → RunExecutionService.runPrepared → AgentRuntime → AgentScopeRuntimeAdapter → AgentScopeReActExecutor → RunGate → 受治理工具/技能网关`。

USER 与 RUNNING Run 在调用模型前提交，started 返回 conversationId/runId/userMessageId。delta 只用于即时展示，assistant 在运行返回后保存。等待审批由 ToolApprovalService 创建待审批记录并使用检查点恢复。RunStatus 目前只有 RUNNING、WAITING_APPROVAL、SUCCEEDED、FAILED、DENIED；ToolApprovalStatus 已有 CANCELLED。完整当前证据 E1～E7 见清单。

## 状态与原子竞争

建议新增 Run 的 `CANCELLING`（停止中，非终态）与 `CANCELLED`（用户已停止，终态）。RunStatus 被工具结果复用，不能机械地把停止请求状态写入所有工具记录；已完成工具保持真实结果。

| 原状态 | 停止处理 | 对外行为 |
|---|---|---|
| RUNNING | 原子登记 CANCELLING，通知实际执行句柄并关闭后续调用入口 | 请求已接收，正在停止；尚不能发送新消息 |
| WAITING_APPROVAL | 原子撤销对应 PENDING 审批，清理检查点，保存安全部分消息和审计，进入 CANCELLED | 已停止；旧决定不可恢复执行 |
| CANCELLING | 返回同一权威状态，避免重复中断/审计/消息 | 正在停止，可查询状态 |
| CANCELLED | 返回既有停止结果 | 幂等成功，可发送新消息 |
| SUCCEEDED/FAILED/DENIED | 返回已经提交的真实终态 | 提示本轮已经结束，不改写结果 |

停止登记与正常完成竞争同一权威状态条件。完成先提交则保留真实终态；停止先提交则正常成功路径不得覆盖停止请求。审批决定、审批过期、生成新的待审批记录和停止也须竞争一致的 Run/审批状态，不能先检查后无条件写入。已接受的审批决定保留历史，不被改写成“从未批准”；恢复执行中的 Run 按执行中停止处理。

停止完成必须等待执行线程不能再派发模型/工具、运行资源收口、在途治理调用结束或得到可靠终止确认。不能因发出 interrupt、关闭 SSE 或超时等待即宣称已停止。若外部调用忽略中断，页面继续显示停止中并阻止本会话新运行；原调用的副作用可能已经发生，不承诺回滚。

## 执行控制与恢复边界

引入与可信 tenant/runId 关联的运行控制契约，实际执行器注册句柄并在 finally 中释放。停止信号贯穿初次执行和审批恢复；默认/第三方 Runtime 必须明确其能力，不得在没有执行控制时返回停止成功。优先保留既有 SPI 的兼容入口，新增方法或能力声明的形式由 T1 确定。

运行门控在下一次模型请求、工具/技能读取/沙箱派发前检查停止信号，并与派发建立清晰的竞争顺序；信号生效前已进入外部网关的调用属于在途调用。工具返回后检查停止状态，抑制迟到成功覆盖和后续调用，同时保留已经提交的真实审计与副作用记录。模型文本快照和停止信号须线程安全、按 Run 隔离。

首版使用当前单实例边界。停止请求和终态持久化，执行句柄只在进程内持有；JDBC 持久化不自动提供跨实例中断能力。接口必须识别执行句柄不可达并返回可行动的状态/错误，不能用本机不存在句柄推断已停止。重启后不自动重放模型或工具；孤立 RUNNING/CANCELLING 记录需保守核对并按运维流程收口，未能核实前不开放同会话新一轮。T1 明确可达性和清理策略并在 T6 验证。

## 部分回答与会话上下文

服务端按 runId/replyId/blockId 收集经过既有脱敏边界的正文快照，保留大小上限，不以浏览器传回正文作为持久化来源。停止收口时保存已有非空正文，关联原 Run 和 USER；没有输出时不制造空 assistant 消息。等待审批前已保存的 assistant 消息应复用或受控更新，禁止重复追加。

部分回答标记“已停止”，停止状态从关联 Run 获得。不得将思考流、原始模型数据或未脱敏参数存入部分回答。已完成的工具摘要可保留；尚无结果的 tool-use 不伪造成成功。续聊时在可信上下文中注明原回答被用户停止，排除未闭合工具块，避免把残缺回答当作完整结论。文件产物沿用只在成功且严格审计完成后交付的规则，停止不能使临时产物成为可下载成功产物。

最终 Run、部分消息、待审批撤销、检查点清理及审计应在可用的短事务边界内协调；模型或工具不得持有数据库事务。memory 模式需采用等价的原子门控与失败策略，不能以没有数据库为理由忽略竞争。严格审计或持久化失败必须保留诊断和可核对状态，不能回退为成功；已禁止的执行也不得因写入失败重新派发。

## 接口与事件草案

建议会话内新增 `POST /api/agents/{agentId}/conversations/{conversationId}/runs/{runId}/cancel` 和同路径去掉 `/cancel` 的 `GET` 状态查询。接口均为待实现草案。

- 停止要求可信认证主体拥有 `agent:run`，且是原运行发起人；查询使用 `agent:read` 和既有资源可见性。
- 服务端验证 tenant → Agent → conversation → Run 归属链，不接受请求体覆盖 tenant、主体或停止结果。
- 请求被登记但未收口返回 202 与权威 runId/status；已停止或已自然结束返回 200 与真实结果。重复请求保持幂等。404 隐藏不存在/跨租户/错误资源关联；403 表示可信资源上的权限或主体拒绝；不支持控制/状态冲突使用稳定错误码和适当 409；依赖或内部错误遵循现有 5xx 边界。
- 保留现有 SSE 事件合同。建议使用 `completed` 携带 CANCELLED 结果；新增可选停止中进度时确保旧消费者不会把它当作成功。等待审批的流已结束时通过停止接口和状态查询收口。
- 所有未知网络结果均通过 GET 核对，不自动重放发送/批准请求。可预期停止属于正常操作，不伪装为模型故障。
- 错误原因使用脱敏中文、稳定 errorCode/errorId；日志记录同号、可信 tenant、principal、Agent、conversation、runId，保持安全审计。

刷新页面时可从已保存 USER 消息的 runId 查询最新运行状态；若不能完整覆盖断在 started 前的情况，T4 提供会话当前活动运行查询。恢复状态不能依赖 localStorage、旧浏览器内存或客户端正文。

## 前端行为

在当前消息输入区增加独立的停止图标按钮，提供“停止本轮”的 tooltip 与可访问名称，尺寸稳定。生成/执行中与等待审批时可用；started 前尚无可信 runId 时显示准备状态并暂禁操作，收到 started 后立即绑定本轮。停止请求后显示“正在停止”，禁止重复提交并保留已展示正文。

用户得到权威 CANCELLED 或其他终态后，重新开放输入与发送；仅关闭流或请求返回 202 不解除忙碌。网络结果不确定时提供查询/刷新入口，保持内容和状态可恢复。待审批取消后卡片变为只读“已取消”，历史仍可查看；旧批准动作不可继续提交。审批恢复期间与初次生成共用同一停止入口和关联 Run。

## 验收矩阵

| 场景 | 必须观察到的结果 |
|---|---|
| 模型输出中停止、模型等待中停止 | 实际中止或协作收口；部分正文持久化；不再启动下一次模型调用 |
| 工具、技能、沙箱在途停止 | 不派发后续调用；已有副作用明确保留；迟到结果不改写停止终态 |
| 等待审批停止 | PENDING → CANCELLED、检查点清理、历史保留，批准/过期竞争唯一结果 |
| 审批恢复中停止 | 原 runId 收口，已接受决定不改写，后续工具被门控 |
| 停止与完成并发、重复点击、多标签页 | 同一权威终态，至多一次最终消息和收口审计，已结束结果不覆盖 |
| 无正文停止、断线、刷新、服务重启 | 无伪造空回答或成功；权威状态可查；不自动重放工具 |
| 跨租户、错 Agent/会话、他人 Run、无权限 | 拒绝且审计；资源与凭据不泄露 |
| 停止登记或收口发生审计/持久化故障 | 有同号脱敏诊断；不伪报停止成功、不恢复派发 |
| 停止后继续发消息 | 只在安全终态后创建新 Run；中断上下文标注明确 |
| 兼容及布局 | v1/既有单轮 API不回归；桌面及 390×844 下控件不重叠 |

以上均为未来验收要求，当前没有执行结果。各 Provider 的上游计费停止、外部系统取消时机不由 CM Agent 单方面保证。
