# 聊天页人工审批界面优化设计

## 背景

聊天页中的高风险工具审批位于受限高度消息面板的下方。运行暂停后，用户可能只看到发送不可用，却没有及时看到审批卡；逐项决定未选齐时，提交按钮禁用原因也不够明确。

## 目标

- 新待审批项出现后将审批区带入视口，并显示待办数量。
- 清楚说明逐项核对脱敏参数、选择允许或拒绝后再提交。
- 让选择控件更容易点击，并在卡片滚动时保持提交区域可见。
- 对只读审批解释可能原因、必要权限及恢复动作。

## 范围与非目标

仅调整 v2 聊天页、共享前端状态提示、样式和 Node 回归测试。不修改服务端审批、权限、API、数据库或工具执行行为；不改变 v1 页面；不自动提交或重放审批。

## 方案与约束

收到权威审批查询结果并完成卡片渲染后，仅当仍有待处理项时定位审批区。缩小消息区最低高度，为审批区和输入区保留空间；允许/拒绝仍需用户逐项明确选择，选齐前提交保持禁用并给出计数提示。只读说明列明发起人限制及 `agent:run`、`agent:approve`，同时建议刷新状态或联系管理员。前端提示不授予权限，服务端的 `canDecide` 仍是权威。

## 验收标准

- 待办加载触发审批区定位，空列表不触发。
- 每项选择提示、选择计数、提交禁用条件及已有审批协议保持一致。
- 只读状态清楚解释限制，不允许再次决定。
- 相关 Node 测试通过，`git diff --check` 通过；真实登录浏览器验收受当前本机页面认证状态约束时如实记录。
