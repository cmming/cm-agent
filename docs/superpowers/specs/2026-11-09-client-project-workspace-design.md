## 背景、目标与范围

用户在浏览器登录远端 CM Agent，在项目页选择已配对的个人电脑，由那台电脑上的本机客户端打开目录选择器，用户明确确认后，在原目录浏览、搜索、引用文件，通过项目会话执行受治理的读取、变更、条件撤销和命令。项目会话继续与一个项目和 Agent 固定关联；目录无需整体上传，但被读取的片段、必要的变更预览和命令输出会经过 Server，模型可收到任务所需内容。用户必须在界面看到设备、来源和数据流说明。

首版为 **Windows x64 交互式桌面客户端、单 Server 实例、JDBC、受控非生产环境**。Server 可在其他受支持的操作系统运行，但不能假定现有 Windows 项目 Bean 能在该平台装配。客户端允许本机 NTFS 等经验证的本地磁盘；网络盘、UNC、可移动介质及无法建立安全根身份的文件系统先拒绝。保留 Server 本机项目，来源不自动迁移或互换。范围包括选择、登记、重命名、归档、文件浏览及分页搜索、项目会话、只读工具、文件计划/预览/应用/条件撤销、固定工具链命令提议/预览/执行/状态/停止、权限审计和恢复。全链路通过验收前默认关闭。

非目标：浏览器直接向 Server 传绝对路径、静默扫描用户电脑、上传完整项目、改变普通聊天的本机客户端授权、多人共享项目、多 Server 实例、macOS/Linux 客户端项目开发、任意命令解释器、生产开放、离线保证、OS 级沙箱；既有 Server 本机项目及一般客户端操作语义不改变。跨平台和生产准入为后续独立需求。

## 当前证据与自主假设

基线 HEAD `0a96c6a0a70c77c20d29e325e276a7eba7ce5010`。`projects.html:20` 明确选择窗口运行在 Server 电脑；`LocalProjectConfiguration.validateDeployment` 将本地能力与 Windows、JDBC、profile 等绑定。`LocalProjectSelections` 的票据、`LocalProjectFiles` 根身份和 `LocalProjectChangeService` 目录备份/Windows 句柄都在 Server 进程本机，不能把远端路径当作 Server 路径。

客户端当前通过 `LocalClientApplication` 单线程轮询、`LocalClientServerClient` 挑战签名领取和回报，`LocalClientTaskExecutor` 调用通用绝对路径操作；`LocalFileOperations` 不以项目为根，不能充当项目执行器。现有 `LocalClientOperationService.invoke` 绑定 Run 授权且进程内 future 等待，不能直接用于建会话前的目录选择或项目页独立浏览，也不能保证跨实例唤醒。`ConversationService` 明确禁止普通 localClient 与项目同时使用；`RunExecutionService` 为项目冻结工具并排除普通业务工具和 Skill；这些规则须保留，新增项目专用设备执行通道。

V26 的项目/根/会话/Run 表、协议 4 及节点身份绑定都是 Server 本机语义，V27/V28 为设备和操作；现有 `JdbcConversationRepository.listVisible` 隐藏项目来源。不能伪造节点或套用服务端加密绝对路径。`LocalProjectRequestBoundary` 保护的是原 Server 本机入口；新增远端入口须设计等价的认证、来源与 CSRF 边界，不能为兼容而关闭原检查。

自主假设：A1 首版用户可在目标设备的交互桌面明确操作；浏览器电脑与目标设备可能不同，必须显示设备名并进行本机确认。A2 用户希望实际修改原文件和执行受控构建；首次版本仅开放“副作用前确认”，保留扩展不同授权模式的能力，但不开放 FULL_ACCESS。A3 Windows 客户端优先，是为了复用可核实的原生保护，非宣称其他系统不能实现。A4 浏览器走 HTTPS（本机回环开发例外按既有安全规则），设备用现有已配对身份及签名协议；默认不改变生产 profile 门禁。以上是设计假设而非用户已确认事项。客户端和 Server 的信任关系需要安装与配对阶段告知：持有当前用户账号的客户端执行权限并不提供恶意本机软件防护。

## 方案与信任边界

在项目页增加“服务端电脑”与“已配对设备”来源；按 capabilities 隐藏不可用入口。为客户端项目引入独立来源类型、专用后端执行接口和客户端受约束项目执行器；可抽取纯协议/规则，但避免搬运强依赖 Server 文件路径和 Spring 的实现后宣称等价。共享项目页的项目列表、会话和审批交互，显式标注来源、设备、在线/不可用及允许的操作。

### 选择和登记（T1、T2）

1. JWT 主体、tenant 和 `project:manage` 来自 Server；选中的 device 必须精确属于该主体且 ACTIVE，服务器创建随机 `requestId`、关联码、限定设备/操作类型和固定截止时间的选择请求，入库并审计。选择属于**创建会话前的独立控制操作**，不得伪装成已有 Run grant；每设备限一个在途窗口，取消、过期、重复请求、无响应均有明确状态。
2. 扩展现有签名轮询协议以发现有版本的控制任务；必须分别核验挑战、签名、设备、请求版本、有效期和来源。客户端支持能力/协议协商；旧客户端不能接收新种类，不可声明在线即支持目录选择。客户端有专门的交互式 GUI 线程：先在用户电脑显示请求来源、关联码和请求含义，用户点确认才打开原生目录选择器；取消、桌面不可用或超时不登记。Server 不得通过浏览器触发后台静默选根，也不信任浏览器提供的路径。
3. 客户端验证根目录、文件系统和目录身份，持久化受当前 OS 用户保护的加密或系统私有根绑定（包含服务身份、设备、随机 rootId/版本和目录身份；密钥丢失须重新选择，不能以同路径猜测恢复）。客户端以设备签名回报短期一次性不透明票据、rootId/身份摘要及经过限制的展示名称，不回传绝对路径。服务端以 requestId 幂等消费票据并事务性创建项目与来源记录、审计；票据绑定 tenant、owner、device、request、时效和版本，不能跨人、跨设备或重复消费。创建结果未知时 GET 同一请求核对，禁止自动重新选择或创建。
4. 服务端创建成功后客户端用幂等确认将本地根从待确认转为绑定；若确认消息丢失，先以签名查询权威绑定再收口；过期或 Server 拒绝则删除待确认绑定。持久的 orphan 清理只删除客户端自己的授权元数据，不删除项目文件。绑定后不提供原位换根：新目录须重新确认并创建新项目；同一路径对象身份变化须停用并重新登记。

### 数据模型与来源（T2、T3）

采用独立 `CLIENT_PROJECT` 来源见证，不把设备 ID 塞进 V26 的 node_id。设计新增设备项目、会话/Run 来源绑定、选择请求和控制任务所需表；保存 tenant、精确 owner、deviceId、projectId、clientRootId、根身份摘要、版本、状态及不可变来源；绝对路径只保存在用户电脑。查询先应用 tenant/owner/设备和来源一致性，再分页。会话和 Run 通过新协议见证（候选 5，实施前重新扫描全库与取值）及固定绑定同事务写入；缺绑定、见证损坏、设备被撤销或来源冲突均拒绝，不能回退普通工作区、V26 或其他设备。现有 V26/V27/V28 是历史，不修改；新迁移按实施时最高版本递增，当前最高 V28，双数据库方言和全部原生中文表/字段注释及完整性约束一致。

必须同步梳理 `ConversationService`、`WorkspaceImportAccess`、`LocalProjectResourceAccess`、Run、消息、审批、产物、查询/取消和 `JdbcConversationRepository.listVisible` 等所有派生资源入口，覆盖存在绑定但来源头损坏、头存在但绑定缺失的拒绝路径；不得只改创建接口。老项目协议 4、老客户端及历史记录按原语义工作。新入口可与已有 `/api/projects` 在 UI 层聚合，具体路由以实现时现有契约评审确定；禁止绕过 Server 本机项目的请求边界。

### 项目文件和开发（T4、T5、T6）

所有操作由 Server 根据已验证来源生成特定 `projectId/rootId/deviceId` 与相对路径的任务；客户端通过自己的受保护根映射、目录身份和句柄逐次校验，不接受 Server/模型提供的绝对路径作为根。根、父路径、文件对象身份及 reparse point、符号链接、硬链接、路径穿越、大小写、替换竞态、敏感/私有目录和应用自身状态区须遵循不弱于现有项目的限制；无法保证时拒绝。固定读写/大小/条目/时间预算，分页搜索显式 partial，模型文件读取保持每 Run 快照和版本语义。每次运行冻结项目、设备、工具集及本轮授权；通用 `local_client_*` 不能替代项目工具，也不得被注入项目 Run。

文件变更采用提议→精确预览→人工逐项审批→条件应用：预览绑定 operationId、版本、摘要、根身份与待变更文件版本；客户端收到获批任务后再次核对并安全执行、写本机持久操作日志和必要的私有恢复材料。任一核对失败拒绝；条件撤销也是新提议和新审批。多文件发生部分成功时如实报告，不能宣称原子。状态可恢复但不自动补做；现有 `LocalProjectChangeService` 使用本地磁盘和 Windows 身份，需抽取或在客户端实现等价能力并由合同测试验证，不得直接远程调用。

命令由客户端显式配置且经验证的固定工具链执行，空工具链不开放；客户端核验可执行文件身份、参数、相对工作目录、环境、预算和审批摘要。所有命令均逐次批准；客户端用户权限决定实际能力，进程可访问项目外文件及网络，界面必须提醒，Windows Job 只负责生命周期，不是沙箱。停止仅代表请求受理，需等待进程退出证据；禁止模型决定工具链绝对路径或隐式调用 shell。输出有界、脱敏，敏感参数和原始输出不写日志。

### 任务、状态和故障（T3、T7）

控制任务与 Run 工具任务显式区分，任务体绑定 tenant/owner/device/project/root/operation/version/类型、有效期限、摘要和批准结果；设备挑战签名、服务端权限与审计、客户端校验三层分别执行。预览/浏览等无 Run 操作使用项目级只读授权；副作用仅从已冻结 Run 的有效审批产生。对领取、撤销、归档、写入有条件更新与明确锁序，不在数据库事务持有期间等待客户端或执行文件/模型 I/O。客户端本地持久化去重账本在副作用前落盘，按 operationId+摘要识别重复；相同 ID 不同摘要拒绝，重启后不能再次执行已领取但结果未确认的副作用。结果回报需验证设备、版本与原请求摘要，查询可幂等；不声称分布式 exactly-once。

断线或超时后区分未领取、已领取/可能执行与已确认；后者未知即 UNKNOWN，禁止自动重发、自动撤销或重新审批。允许同设备提交已有持久结果供核对；无法证明时人工确认外部状态并终结原意图，不能凭猜测改写为成功。撤销/归档和启动许可的竞争按 R1 仲裁规则处理，已许可或已开始的操作不得承诺即时撤销；已经启动的操作尽力停止并按可观察结果核对。明确本地日志、服务端审计、TTL、锁、恢复材料保留与清理策略，防止清理未决操作或用户文件。

## 安全、权限与界面（T0、T8）

沿用项目权限和 `agent:run`、`tool:grant` 等现有策略；设备配对、项目来源、执行授权三者互不替代。注册/浏览/审批/运行/归档、断线、撤销及安全拒绝均记录脱敏审计；失败响应和日志关联同一 errorId。Server 不能因持有设备 ID 或模型输出而获得用户电脑访问权。可信 Server 仍可向已授权设备提交任务，本机客户端只能在已验证的有限任务和有效授权内执行；不承诺防御已攻陷的当前用户账号。未经验证的弱本机客户端能力不能成为项目隔离保障。

项目页需显示来源和设备名称、能力协商与最近在线证据（不是 ACTIVE 即在线）、选择请求关联码/进度/取消、离线与重新连接、根失效、归档只读、状态未知的核对入口。审批同时展示设备、相对路径、精确差异或命令、可见副作用及批准范围；文件/命令默认逐次批准。快捷入口应保证浏览器端不直接收到本机绝对路径或本机身份密钥。内容显示、模型输入、日志、操作审计分别遵循现有脱敏和预算；用户明确知悉片段传输。

## 验收与验证（T9）

必须覆盖：A) Windows 客户端与不同机器上的非生产 Server，经真实配对、真实目录窗口完成关联码匹配和取消；根目录不是 Server 目录，原目录无需整体上传。B) 项目页列/读/搜索/分页/partial、引用、项目会话与模型按需读；精确预览后应用、冲突拒绝、条件撤销；配置固定工具链后命令、停止及输出。C) 跨租户/owner/设备、伪造路径、重放票据、超时、撤销、档案头损坏、链接/目录替换、归档并发和离线 UNKNOWN 均拒绝或按约定收口。D) 强制人工审批、设备/目录/摘要一致、网络失败不重复副作用；安全错误码、errorId、日志及敏感数据不泄露。E) 老 Server 本机项目和普通聊天/客户端保持行为；旧客户端能力不足明确提示。F) PostgreSQL 16 与 MySQL 8.4 迁移、原生中文注释、租户隔离、事务竞争和重启；按 AGENTS 使用 Rocky 的 Docker/Testcontainers，远端提交和工作区状态与待测内容一致。G) Windows 真机分别测试客户端退出/重启、密钥丢失、断线、进程树及授权恢复；浏览器桌面/窄屏、键盘和实际模型端到端。测试凭据和个人文件禁止写入仓库或日志。

当前仅为设计，以上能力和测试全部待实施；其他阶段和平台不借用历史测试通过结论。

### 1. 装配、协议来源与发布栅栏（T3、T10、T14）

引入单独的客户端项目开关和安全条件，默认关闭，不能依赖开启 `cm-agent.local-projects.enabled` 才装配远端项目；在 Windows 和 Linux Server 的受控单实例 JDBC、受支持 profile、真实审批 Runtime 上分别验证。Server 本机项目的原开关、Windows 选择器、状态锁和请求边界原样保留。启动时校验数据源、审计、持久密钥、客户端设备协议和 Runtime 的**远端项目保护合同**；依赖缺失时新功能拒绝，不能降级为普通会话、现有普通设备授权或 Server 本机目录。远端请求必须有基于已验证部署配置的精确 Host/Origin、同源/Fetch Metadata、自定义行动头或等效防护、认证及 RBAC；明确无 Origin 的客户端请求策略；不得任意信任或全局开启代理转发头，代理部署在首版未验证前不支持。JWT 被盗或运行在受信页面的恶意脚本不在同源防护承诺内。

先在 T0 建立具体入口清单及测试映射：项目 CRUD、目录/预览/搜索/选择、会话列表与消息、Run 列表/详情/停止/SSE、审批创建/查看/决定/恢复、项目操作/命令/撤销/归档、运行快照、审计和产物。分别列 Controller→Service→Repository→Runtime/Gateway→适配器以及关闭开关后的路径；入口遗漏不能标记 T3 完成。扩展或抽象 `ProjectRuntimeContext` 对来源绑定的强类型约束，并让适配器、工具目录、审批和恢复识别新来源；禁止把设备 ID 伪造为 V26 node/root。每层均以 tenant + 精确 owner + project + 来源 + 设备/根版本 + 会话/Run 做一致性校验，客户端控制变量不能直接决定工具集合。普通会话 `localClient` 的互斥仍有效；新来源通过专用项目上下文与受治理网关发送任务。

迁移前先验证新老二进制与新来源互访：旧版本的协议判断只认识 4，DB 即使新增候选 5 的 CHECK 也**不能证明旧代码会安全拒绝**。首版采用维护窗口、单实例停止旧进程、备份、迁移、部署新程序、验证全路径后才允许新来源写入；禁止混合版本/新功能写入期间回滚旧二进制。关闭新功能仍须识别并拒绝新来源的所有派生访问，历史查询在能力关闭时不得绕回普通列表。若确需回滚，先离线停机，按已验证方案隔离/迁移所有新来源及派生见证并完成恢复演练；无法证明时禁止回滚或旧版启动。不要要求删除用户数据。验证 V26–V28 历史无变更、PostgreSQL/MySQL 约束/索引/原生注释、事务、owner 二进制比较和旧代码可见性；候选 5、迁移号及所有 CHECK/Repository 白名单实施时再审计。

### 2. 控制任务、关联与双端状态（T1、T2、T11）

将任务协议逻辑上分为：①登录主体发起的目录选择控制任务（无 Run，仅项目管理权限）；②项目级有界只读查询（无 Run）；③绑定 Run、工具调用和审批的副作用任务。消息是版本化、类型白名单和完整身份上下文的信封，绑定服务 audience、tenant、精确 owner、deviceId、requestId/operationId、project/root 版本、意图摘要、nonce 与截止；未知字段/协议版本或能力不足明确拒绝。HTTPS 校验服务端身份，设备请求按现有挑战签名验证；签名设备请求并不自动证明 Server 所返回任务本身已被独立签名，客户端信任经验证的 Server/TLS，不能宣称端到端 Server 签名已存在。

交互选择与命令不得占住唯一领任务线程：控制通道独立于执行工作线程，能够接收取消和状态查询；每设备单 GUI 窗口、每项目副作用串行，有限队列、请求体/结果体/片段、并发数、心跳、TTL 与清理配额设明确可配置上限及硬上限。关联码只辅助用户比对浏览器与目标设备，仍需在设备上看到 Server 身份、设备名与用户确认；不当作认证、授权或加密证明。选择超时后窗口结果不能迟到签发票据；无交互桌面、锁屏或未确认均失败关闭。浏览器关闭、重复点击和客户端重启按 requestId 查同一个请求，不重复弹窗。

选择 Server 侧状态为 REQUESTED→CLAIMED→SELECTED→REGISTERED 或 CANCELLED/EXPIRED/FAILED；客户端侧为 PENDING→SELECTED_PENDING→BOUND 或 CLOSED，且每步 CAS/持久化到私有目录。设备回报同时含请求、设备、rootId、根身份摘要、一次性随机值、期限和签名上下文；Server 验签、验绑定并单事务消耗选择凭据、创建来源记录与审计，同一凭据重复只返回原结果，变化的请求/摘要冲突。Server 已创建但绑定确认丢失时，客户端先经签名只读查询同一 requestId 的权威结果再转 BOUND；Server 无记录、失败或期限届满仅清理本客户端待确认元数据。设备重装/身份密钥丢失或原绑定无法验证时须重新配对并重新确认、建立新项目，禁止根据同名路径接管历史。明确客户端存储的 OS ACL、加密密钥与崩溃安全写入；不能凭 Java 私有目录命名宣称系统级机密性。

### 3. 审批、派发、撤销和崩溃顺序（T5–T7、T12）

Server 权威状态按项目意图使用 PROPOSED→WAITING_APPROVAL→PREPARED→START_GRANTED→RUNNING→终态，异常进入 UNKNOWN；名称与现有状态映射在实施时固定，PROJECT 操作保持用户可见且独立于传输状态。客户端持久账本使用 RECEIVED→DURABLY_ACCEPTED→EFFECT_STARTED→RECORDED，关键阶段持久写入并验证；operationId+摘要全局唯一，重复同 ID 只返回已有证据，不再次执行，不同摘要拒绝。登记和每个转移都绑定 tenant、owner、device、root、Run、toolCall、操作版本与摘要；到期、审计失败、设备/项目版本变化时不能产生新许可。

关键次序：①先锁定并显示由客户端产出的受控预览及原始版本摘要；②用户逐项审批版本/摘要；③Server 在短事务里同时复核未撤销权限、设备和项目版本、审批以及状态 CAS，提交一次性短期启动许可并审计；④客户端验证匹配的许可、项目根及版本，在持久记录后立刻执行。撤销/归档与③按同一数据库行锁/CAS 竞争：撤销先提交则不给许可；许可先提交则原意图已获准，后续撤销只能尽力通知/停止，**不能保证客户端在撤销提交后尚未开始的操作绝不启动**。短期许可仅缩短窗口，不能消除网络分区、时钟偏差及本机调度竞态；客户端本地单调时钟测量租约并在副作用前重新校验，异常时拒绝开始；Server 时间权威及允许偏差/超时数值在实现时确定并测试。严格的“撤销先于真实本机 syscall 生效”超出此分布式合同，不作承诺。

取消区分 CANCEL_REQUESTED、已确认未发生、已结束及 UNKNOWN；请求成功不是进程树退出或文件回滚。设备撤销后仍能否用原公钥提交**仅限指定 operation、版本、摘要的一次性只读回执**，需新建最小权限认证路径并防重放，不能使用该路径领取、修改或重新授权；若设备已删除密钥、身份不可验证或回执无法证明，保留 UNKNOWN，走用户人工核对与原意图终结。仅当完整、不可冲突、与受信持久日志和摘要匹配的证据足够时可受控对账为终态，审计原因；现有 `complete` 不接受 UNKNOWN 晚到结果，不能宣称现成支持。审批过期、权限变化、设备撤销、目录身份变化时恢复流程不得沿旧快照扩大权限。

### 4. 数据和审批可见性（T4、T5、T8、T13）

清晰区分：原始字节版本摘要用于条件写，脱敏后视图用于模型/页面，审批摘要覆盖**完整规范化操作意图和实际待应用字节**；不能把脱敏文本重新写回或用视图哈希冒充原始文件哈希。预览含需要跨 Server 传输的数据，TLS 和静态密文保护、用户提示、审计及短期保留策略均须明确。若脱敏隐藏了本次变更的任意内容、路径或命令参数，首版拒绝在线审批并提示人工处理；不提供“已看过脱敏内容就批准完整隐藏内容”的绕过。脱敏是尽力降低泄露，不保证识别所有敏感数据。

原始代码、文件名、目录名、差异、输入和输出都可能包含敏感信息：定义传输/Server 临时缓存/加密快照/模型提供方/浏览器/客户端恢复材料的生命周期、大小预算、访问权限和可检索 errorId；默认不写明文日志或通用审计。模型提示、文件和命令输出均是不可信数据，不能改变系统指令、设备或根绑定；工具是否调用由 Server 固定策略和用户审批共同决定。归档不删除本机文件；清理清单、快照和恢复材料只在确认终态且达到保留期限后进行。UI 不能承诺所选目录对命令构成沙箱，也不能宣称不会上传任何内容。

### 5. 可执行验收补充（T9、T14）

增加四张逐行矩阵并在实施账本记录命令、环境、期望/实际、证据及未执行项：①入口×tenant/owner/device/source×开关开启/关闭/缺失/损坏；②每个控制/操作状态在写前、写中、写后、回报丢失及两端重启的故障注入；③选择/撤销/审批过期/目录替换/归档与启动许可的两种提交顺序，验证不承诺超出许可顺序的撤销；④老客户端/新客户端、老数据/新数据、旧 Server/新 Server 的停机升级与回滚禁令。另覆盖长命令期间取消能送达、输出丢失/磁盘满、预览掩码变更拒绝、原始哈希与脱敏视图不混淆、prompt 注入不越权、真正跨机器目标与用户确认、客户端重装/被撤销回执、真实 Provider 传输、窄屏/键盘。代码审查和自动化测试不能替代 Windows 原生目录选择、安全文件句柄与进程树真机验收。

### 6. 接口与运行合同草案（T2、T3、T11）

以下是新契约的**设计建议，不是现有路由**；具体路径和字段由实施 T0 核对现有控制器后确定，不能静默改变现有 `/api/projects` 行为。

| 动作 | 发起者及鉴权 | 契约与失败行为 |
|---|---|---|
| 查询设备项目能力 | 已认证用户 + 项目读取权限 | 返回开关、可用协议版本、客户端能力和最后一次带签名活动时间；无能力、过旧和离线分别说明，不以 ACTIVE 充当在线。 |
| 发起/查询/取消选择 | 已认证用户 + 项目管理权限 | 发起指定所属 ACTIVE device 和随机 requestId，返回 202、关联码及截止；同一 requestId 同参数返回同一请求，参数不一致 409；查询不泄露绝对路径，取消与客户端领取竞争由 CAS 裁决。 |
| 领取选择及签名回报 | 固定配对设备 + 单次挑战 | 客户端领有界、版本化控制任务；结果只允许确认/取消/失败，确认包含一次性绑定材料、根身份摘要与绑定版本；迟到回报拒绝。 |
| 提交/查询项目登记 | 原主体 + 项目管理权限 | 服务端以选择请求为幂等键事务消费票据并建立来源；跨主体统一拒绝；状态未知只 GET 同请求，不能自动重新创建。客户端再签名查询结果完成本地绑定。 |
| 目录/文本/搜索 | 原主体 + 项目读取权限 | 项目级只读请求，无需虚构 Run；先鉴权和预算检查再排队，以 202 + 请求 ID 轮询状态，不持有 Web 线程等待设备；结果受 tenant/owner/device/root/版本约束并限期加密保存，超时返回可核对状态。 |
| 运行/审批/操作 | 原主体 + 项目、Agent、工具和审批对应权限 | Server 从可信绑定创建专用项目 Run；变更或命令按提议、预览、审批、启动许可推进。不得信任前端提交的设备、根或工具集合覆盖服务端绑定。 |
| 停止/状态/回执核对 | 原主体的操作控制入口；设备回报单独鉴权 | 控制请求与执行通道分离；重复取消仅读当前状态；设备失联或签名不可验证时保留未知状态，审计人工核对。 |

选择、浏览与模型读取均采用固定上限，建议默认选择请求 2 分钟、只读查询 30 秒、执行前许可 10 秒且均有独立配置硬上限；这些数值为待压测的默认方案，不能作为现有实现事实。命令最大 30 分钟需与 Run 模型工具超时、审批 TTL、客户端心跳、HTTP 请求时限分层协调：启动后的命令作为持久操作异步运行，短请求只提交/查询状态，不能同步等待整个命令；模型调用、运行状态和已启动进程的关系必须由 T3/T6 落实，不能在模型超时后把仍在运行的进程报告为已停止。客户端定期上报有界状态，服务端中断不造成重复派发。

数据表最少分别承载：`client_project`（租户/主体、设备、根引用、来源版本及项目状态）、`client_project_selection`（用户请求、期限、状态及幂等键）、`client_project_binding`（项目到会话/Run 的不可变来源见证）、`client_project_task`（任务种类、版本、摘要、领取/回执状态）。名称为候选；是否拆表、外键、索引和协议见证必须依据有效 DDL 评审。单一 `(tenant, owner, requestId)` 的选择唯一约束和 `(tenant, device, operationId)` 的操作唯一约束只是最低要求，还需按关联字段验证摘要一致、索引分页且在 MySQL 对 owner 使用与仓库一致的精确比较。根原始路径和恢复私钥不进入 Server，源文件片段与预览若需要暂存只能在受控加密存储中保留，TTL 过期不等于可删除未决证据。

每个新增 endpoint 需明确请求/响应大小、状态码、稳定 errorCode、errorId、错误脱敏、限流和不重复的审计事件；认证失败/跨租户及不同主体不泄露资源存在。针对排队拥塞、设备版本不支持、设备离线、选择过期、根变更、审批摘要变化、权限撤销、结果未知分别返回可区分的受控错误。上下文注入从授权绑定而非请求体重建；失败时是否允许重新选择/重新发送由权威状态决定。

### 7. 平台能力与数据恢复验收补充（T4–T7、T14）

客户端第一版对 Windows 文件系统只开放已经通过真实句柄与身份保护测试的文件类型和操作；文件移动、删除及条件撤销若不能证明身份、安全描述符、原内容和并发替换的恢复语义，则该子能力标记不支持并阻止功能总体验收，不用通用 `LocalFileOperations` 或简单 `normalize/startsWith` 代替。按崩溃点证明恢复材料持久化先于副作用、记录对象身份和 ACL，磁盘满/密钥丢失/日志损坏必须拒绝或 UNKNOWN；本地状态所在目录只供当前用户访问，并防止自身被选作项目。

每个项目同一时刻最多一个副作用处于已许可或在途；多会话、两个客户端进程及选择归档竞争必须跨进程排他或使用服务端唯一约束、租约与客户端可靠锁共同证明；无法取得锁则明确拒绝，不仅依赖 JVM 内 `synchronized`。项目归档沿用现有“活动 Run 或未决副作用阻止归档”的原则：若运行、启动许可、UNKNOWN 或待核对操作存在，拒绝归档并引导先核对；归档提交后不签发新许可，但已经签发/发生的状态仍按第 3 节处理。设备撤销可以发生在已许可操作期间，必须展示该窗口并提供后续人工核对。

客户端更新需验证旧版无法领取新任务、未知版本不降级；客户端崩溃后由本地持久账本和 Server 权威记录共同核对。跨端时钟误差、系统休眠、回拨、断网、断电、Windows 注销、Job 是否仍运行、锁释放和目录重新挂载均列入 T14 真机矩阵。签名回执只证明被配对设备密钥签发，不单独证明磁盘副作用的事实；对账需结合本地账本、文件版本/对象身份或进程结束证据，证据不足则 UNKNOWN。

### D1：明确受管工具与两种运行器的载荷保护（T15）

新工具使用独立、租户稳定的 `cm-agent/client-project/v1` ID 命名空间及 `client_project_*` 模型可见名称；具体函数覆盖本工作包的列/读/搜索、变更提议/应用/条件撤销、工具链及命令生命周期。不得复用 `project_*` ID 后指望 endpoint 决定设备，不得注册可经普通调试/MCP 调用的通用 ToolRegistry 执行器。服务端网关精确验证 ID→种类→权威来源→Run 固定目录→权限和风险，再送往专用客户端项目执行器；名称、endpoint、模型参数不能覆盖执行位置。普通会话排除两类项目受管工具；开关关闭仍识别新 ID 并拒绝，不能落到通用工具分支。Agent 被授予两套目录时，Run 只暴露匹配当前来源的一套。

采用统一强类型的受保护项目上下文表达 Server/Client 两种来源，保留旧构造及协议 4 的兼容行为；内部绑定必须区分类型，不能伪造本机 binding。`AgentScopeToolBridge`、ReAct 和 Harness 的工具输入、进度、失败、思考块处理、审批、最终消息、ToolCall、SSE 与加密检查点都必须识别新来源。仅展示允许的受控摘要和输出；读取给模型的内容不自动获准进入普通轨迹。Harness 保留原生文件/Shell/持久化追踪禁令。用测试专用敏感标记覆盖成功、异常、超时、审批恢复、停用功能和两种执行模式，断言原始文件/补丁/参数未泄露到不允许的存储和展示通道。复用工具授权不代表可复用原本机 I/O 实现。

### D2：物理根冲突与写后快照（T16）

首版选择**拒绝重复及重叠的活动根登记**：同一 Windows 用户下，卷/目录对象身份相同、路径别名、祖先/后代目录与已绑定根重叠时，不创建第二个项目；原请求重试只返回原项目。客户端需有该 OS 用户范围的共同根登记及跨进程锁，不因 `--state-dir`、重新配对、不同 Server 或新随机 rootId 分裂；不能可靠协调时拒绝新增绑定而非声称已隔离。客户端身份/根映射丢失仍不凭同名路径接管历史；重新登记前必须先处理历史未决根隔离。外部编辑器、不同 OS 用户或主动篡改受信客户端不在该排他保障内，仍依赖对象/内容版本检查，命令不因此成为沙箱。Server 本机项目或普通客户端等其他执行来源不自动参与此锁，也不能据此允许与新来源安全并行操作同目录；同机使用须保持操作互斥并明确限制。

物理根状态独立于项目状态保存；UNKNOWN、已许可和未证明退出的进程均阻止相同/重叠根新副作用。本地持久排他代次应绑定操作和启动许可；晚到的旧许可不能在新代次执行，但代次变化本身不能停止已启动 Job。根冲突校验、选择登记和修改必须防并发注册窗口；单 JVM 锁、字符串 startsWith、随机 ID 以及 Server deviceId 均不足以证明物理对象不同。

写前按已批准意图预留 Run 快照写后空间；写后只能依据对应 operationId/摘要的已验证回执和批准意图幂等推进原字节 hash、脱敏正文、删除/移动见证及快照代次，不能重新从变化后的磁盘读取来假装原批准内容。部分成功逐动作记录；未确认动作冻结同轮后续相关读写。客户端已写成功而 Server 快照保存失败时，保留“文件已执行，快照未同步”的可检索记录并失败收口当前 Run，不能重发 apply；后续只做对账。迟到旧读取结果必须匹配当前快照代次，禁止覆盖写后版本。保持 R1 中原字节摘要、脱敏视图与审批摘要的区别。

### D3：命令与 Run、隔离和停止的生命周期（T17）

首版采用现有项目的完成语义：命令工具可短请求返回句柄，但模型回答结束不等于 Run 成功；所有关联命令退出或进入明确的失败/未知收口之前不能宣告 SUCCEEDED。远端 Run 完成屏障必须有独立有界期限和可中断等待，不照搬 core 无界 `awaitQuiescence()`；等待期间不持有 JDBC 事务或 HTTP 请求线程。超过通信/运行预算时，Run 可进入现有 FAILED 状态，相关操作为 UNKNOWN、根保持隔离；正常停止仅在有可信进程树退出证据时报告已停止，不能创造未定义的 Run 状态来遮掩结果。

Run 终态撤销**新执行**许可，但保留操作来源记录、只读结果查询、停止和对账入口；这些入口按长期来源及特定操作重新授权，不依赖已删除的 Run grant/模型检查点，也不允许重启命令。设备被撤销后的受限回执按 R1 规则；身份不能验证时本机仍需提供用户本地停止入口和本地受管进程超时/watchdog，Server 不假造成功。Server 重启、模型提前完成、再次等待审批、读取超时及权限变化的每条链路都必须保持上述区分。

人工“接受可能已发生的副作用并终结意图”只改变逻辑处置状态，**不自动释放物理根隔离**。解除隔离必须确认未使用许可失效且客户端持久拒绝旧代次、所有已启动 Job 已退出或有可信的系统重启/本地核对证据；无法证明则继续阻止新副作用。不得用 TTL、Run FAILED/CANCELLED、删除项目、归档或重新登记绕过隔离。客户端必须提供可行动的核对信息，不能陷入仅有“失败”但没有停止/恢复入口的状态。

命令审批冻结客户端工具链定义版本、可执行文件身份、argv、工作目录、环境和实际构建位置的相关配置摘要，至少覆盖旧实现已经保护的构建文件；审批后 pom.xml、子目录构建配置或工具链定义变化应拒绝并重提案。冻结配置不等于冻结所有脚本、插件、依赖或外部服务，也不保证依赖下载后的行为；这些剩余风险在命令精确预览中说明。

### D4：页面来源、异步请求和历史合同（T18）

首版采用 `projects.html` 内两个来源分栏：Server 本机沿用 `/api/projects`，客户端项目用独立 `/api/client-projects` 路由族（设计路径，实施前仅核对冲突，不得悄悄修改旧 API）。分别查询 capabilities、列表、分页和详情，暂不将两个列表截断后在浏览器混排成一个分页列表；Server 本机能力关闭/不可用不能禁用客户端项目入口。每次选中的资源键包含来源类型和 projectId，所有交互持续显示设备。

新增请求适配器处理 202→状态轮询→终态数据，不能直接把任务信封传给旧的 tree/text/search renderer。请求必须绑定登录 sessionEpoch、来源、设备、project/root 版本、会话和 UI 加载代次；导航、退出、切项目后丢弃迟到结果并停止页面轮询，不能把页面 AbortController 当作服务端已经取消操作。读操作成功缓存再次交付时仍复核主体和来源；过期、版本变化和部分搜索结果不能当最新完整数据。刷新后的选择/登记/命令结果按同一个 requestId 或 operationId 查询，不自动补发写请求。规范 requestId：浏览器生成不可预测的幂等键，Server 按主体作用域校验/固定，真正的授权票据与启动许可由可信流程生成，requestId 自身不是权限。

客户端来源只呈现 ASK_ON_EFFECT；后端同样拒绝该来源的 ASK_ON_RISK/FULL_ACCESS，不只禁用下拉框。Server 本机项目三种旧模式保持。确认按钮、状态查询、命令输出等通过来源适配器路由，不能把新 operationId 送入旧本机审批或命令路径。

区分设备实时能力和已存历史：离线、设备撤销、根失效时禁止新的文件访问/执行/审批恢复，但原主体在仍具读取权限且来源记录完整时可以查看已保存项目元数据、会话、审批和操作历史，标为历史而非当前磁盘状态；不为读历史触发设备连接。源见证损坏、跨主体、读取权限撤销或功能完全关闭仍按既定拒绝规则，不借历史读取解密新内容。仅 ARCHIVED 一种状态不足以表达上述组合，视图需分别表示项目生命周期、设备可用性、根有效性、物理隔离和可执行能力。

### R2 残余风险与实施门禁

R2 没有发现需要推翻“专用来源 + 本机确认 + 有界授权”方向的架构阻断，但当前证据不足以直接进入业务实现。T15–T18 及 C01–C10 未完成前，远端客户端项目必须保持默认关闭；T9 不得用单元测试、模拟设备或历史本机项目证据替代 Windows 跨机器、真实目录身份/进程树、真实 Provider、浏览器代际和 Rocky 双库验收。

以下风险只能被明确披露和控制，不能被当前方案消除：客户端当前 OS 用户、设备密钥或已授权本机环境被攻陷时，攻击者可执行该用户可执行的操作；外部编辑器、不同 OS 用户及主动篡改的本地软件不受客户端共同根锁约束；命令引用的脚本、插件、下载依赖和外部服务不在工具链/构建摘要的完整快照内；客户端信任经验证的 Server/TLS，而设备签名不自动验证 Server 下发的每个任务；模型或 Server 可见的获授权内容仍有提供方传输与留存风险；Windows 重启证据不足时物理根可能长期保持隔离，需要可行动的本机停止与人工核对。任何“已接受逻辑 UNKNOWN”“Run 已失败/取消”“项目已归档”“授权过期”都不能单独解除物理根隔离或重启命令。若无法满足这些门禁，实施者应缩小能力、保持来源关闭并记录阻塞，不能降级到通用绝对路径工具、普通本机客户端授权或 Server 本机路径。
