# 强制生成既定范围内代码注释设计

## 背景

现有代码注释规范已经规定应主动判断注释需求，但未直接要求 Agent 在判断需要注释后必须把注释写入代码，导致实现、测试和文档完成时仍可能遗漏应有注释。

## 目标

在不改变既有注释适用范围、注释密度和质量标准的前提下，要求 Agent 对已判定需要注释或 JavaDoc 的 Java 代码实际生成中文注释。

## 范围

- 修改根目录 `AGENTS.md` 的代码注释与 JavaDoc 规范。
- 记录本次规则调整的设计、计划、实现和进度。

## 非目标

- 不扩大哪些代码必须注释的既有范围。
- 不修改业务代码、测试、构建或数据库结构。
- 不引入自动化注释覆盖率检查。

## 方案

在现有“主动判断”规则后增加强制落地条款：只要根据既有规则判定需要注释，Agent 必须在同一次代码修改中写入中文注释或 JavaDoc；仅在分析、计划、测试说明或最终回复中说明不构成完成。该条款明确不扩大既有范围。

## 验收标准

- `AGENTS.md` 包含强制实际生成注释的明确约束。
- 条款明确沿用既有规则，不新增注释范围。
- 新增文字为中文，且不影响其他仓库规则。
