# V3 聊天工作区设计

日期：2026-11-21；主题：`console-v3-workspace`；修订：R0；工作模式：`mode=default`；任务：T0～T5。

## 背景、目标与边界

前轮[独立 Sites 原型](https://cm-agent-codex-workspace.poetic-lark-9729.chatgpt.site/)展示了 Codex 式项目与会话导航、聊天主区和按需展开的上下文。用户要求在当前项目中生成 V3，沿用布局、保留已有功能并接入真实后端。

V3 的目标是让日常使用从聊天工作区开始，管理页面保留独立 URL 与完整操作能力；版本化前端共享既有服务端 API、认证、租户、权限、工具治理与持久化链路。V2 仍可访问，不以新布局删除旧能力。当前范围不包括新业务 API、数据库方案、通用自由终端、默认安全策略放宽或生产环境部署。

## 当前事实与假设

当前 V2 位于 `cm-agent-console/src/main/resources/META-INF/resources/console/v2/`，具有 login、chat、projects、overview、agents、model-configs、tools、skills、runs、audit、local-client 十一个 HTML 入口。模块为静态资源 JAR；受控同文档导航、API 会话 Cookie、聊天 SSE、审批、停止及项目工作流由共享脚本承载。V3 页面保留这些业务 DOM，版本导航、壳的挂载/释放与项目视图重排是需要适配的接缝。

参考 Site 源码位于 `F:/java/cm-agent-sites/cm-agent-codex-20261120/`，其示例数据、浏览器持久化业务状态和预设回答不能迁入 V3。原型的 33 项检查只证明当时静态布局交互，不证明本次真实产品或真实后端可用。

## 决定

| 编号 | 依据与采用方案 | 影响 |
|---|---|---|
| D1 | 用户要求依 Site 布局生成 V3；采用浅色项目/会话侧栏、中央聊天和可折叠上下文 | T1、T2 以聊天为默认工作场景，不另开视觉方向选择 |
| D2 | 用户要求保留功能并接真实后端；复用既有共享业务逻辑、DOM 契约和 API | 不把模拟页面或纯链接目录当作功能迁移；不复制一套权限或执行逻辑 |
| D3 | 未要求撤销 V2；保留 `/`、`/console` 等原有默认入口和 V2 URL，新增 V3 根入口与固定短路径；V3 登录后默认进入聊天 | 保持旧入口兼容，直接选择 V3 才进入新工作台；同版本 `returnTo` 必须经过白名单校验 |
| D4 | 原有安全边界属于产品契约 | Cookie、JWT 内存生命周期、权限、租户、审批、审计和脱敏保持服务端权威 |
| D5 | 管理操作需要原有独立地址和完整能力 | 管理页复用工作台外壳，保留资源详情、表单、授权、调试和历史 |
| D6 | 真实环境与模拟检查证明范围不同 | 明确记录真实 API、真实模型/设备执行、浏览器与测试替身的各自证据，不用历史通过替代新验收 |

D1、D2 来自用户明确指令；D3～D6 是当前范围内的工程取舍与约束，不伪称用户逐项确认。D3 将初稿的保守假设定为兼容方案：既有默认入口不切换，新增版本入口和 V3 登录默认聊天的行为在生产说明中区分。默认模式不主动逐项咨询，发现与当前代码或用户新指令冲突时定点修订并记录依据。

## 结构与调用链

左侧承载当前工作空间中的项目与会话，以及可折叠的平台管理导航；普通聊天与项目聊天的归属、Agent 和权限语义继续区分。主区保留会话头、运行/审批状态、消息记录和视口内输入区；文件、运行详情与审批在需要时打开上下文区域。窄屏改为可关闭导航与上下文覆盖层，保持关键操作和键盘可达。

调用链仍为“V3 页面操作 → 现有共享客户端逻辑 → 同源 `/api` → 现有 Controller/编排/Repository/运行时 → 已有流式或 JSON 结果 → 页面反馈”。模型由 Agent 绑定的有效模型配置决定，不能以原型模型菜单绕过；设备配对标签不推断在线状态。恢复、审批、停止和断线核对使用原有服务端状态，不从 UI 选择推定成功。

共享客户端使用显式 V2/V3 白名单识别版本与同版本返回路径；壳的挂载和释放随同文档导航执行。项目视图切换先还原被布局层移动的业务节点，再释放和克隆新项目节点，防止同一工作区出现重复 ID 或遗留事件归属。手机关闭侧栏时，同时处理可达性和背景交互状态，视觉隐藏不能保留不可见焦点入口。

错误展示保留可行动中文原因及适用的 `errorCode`、`errorId`；权限、资源归属、工具授权和审计由服务端判断。浏览器隐藏控件只改善交互，不构成安全控制。输入草稿、JWT 和文件数据遵守原有生命周期，不引入原型式长期本地持久化。

## 验收标准

以[清单](../checklists/2026-11-21-console-v3-workspace-checklist.md) T0～T5 为准：十一个版本化入口、现有功能保真、真实后端链路、桌面与窄屏任务完成、安全与失败边界不退化，并有与本次代码对应的验证证据。完整业务验收不能仅由资源存在、页面截图、模拟响应或语法检查推导。
