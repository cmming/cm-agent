## 需求与范围

`local-client.html` 是浏览器用户管理本机设备连接的页面，负责：

- 接收本地客户端 `pair` 命令生成的签名配对包。
- 解析并在页面上预览设备名称和平台，不把未确认的设备当作已连接。
- 将配对包提交给服务端，确认后把设备绑定到当前认证主体和 tenant。
- 列出当前账号已配对设备，查看设备详情并执行撤销。
- 支持刷新设备列表；设备数量和列表包含服务端返回的活跃与已撤销记录，状态必须分别显示。
- 设备详情展示平台、设备标识、配对时间、状态版本和最近更新时间；撤销需要二次确认并携带读取时版本。
- 明确展示授权边界、命令账号权限、Run 结束失效和 UNKNOWN 不复用原则。

本页面不负责执行本机文件、网络或命令；这些操作由本地客户端执行，并由聊天页选择已配对设备和授权模式。页面也不显示设备在线状态，不能用推断状态欺骗用户。

### 授权模式与本页边界

| 页面名称 | 代号 | 设备客户端作用域 |
|---|---|---|
| 操作前询问 | `ASK_ON_EFFECT` | 文件、网络、命令及未知外部副作用逐项确认 |
| 帮我批准 / 高风险时询问 | `ASK_ON_RISK` | 可信低风险操作自动，高风险和未知操作确认 |
| 完全访问 | `FULL_ACCESS` | 当前 Run 内，在用户操作系统账号权限、设备身份、租户、工具 grant 和审计约束下自动执行 |

模式由聊天页随 Run 提交，不在 `local-client.html` 选择；本页只管理设备。`FULL_ACCESS` 不能解释为自动提权，也不能与项目内固定 `project_*` 工具授权混用。

非目标：桌面 GUI 自动化、长期全局授权、用户账号提权、未经配对的设备调用、把 Server 文件系统当作浏览器电脑。

## 执行边界

- 设备私钥留在用户电脑；浏览器只转交客户端签名包，不持有设备私钥。
- 首次配对必须由本机确认，浏览器确认不能替代设备持钥证明。
- 浏览器确认后仍须等待客户端轮询并保存设备标识；服务端已配对不等于客户端已完成。
- 设备私钥优先使用系统密钥链；不可用时使用本地口令保护，不能静默降级为明文。
- 授权模式只影响当前 Run；停止、终态、撤销或过期后不再授权新操作。
- 设备客户端完全访问按用户账号范围解释，但不得自动提权或绕过 Server 认证、tenant、工具 grant 和审计。
