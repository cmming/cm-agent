## 当前事实、范围和假设

- 项目页选择器当前在 Server 电脑打开；`LocalProjectConfiguration`、`LocalProjectFiles` 和 V26 绑定 Server 本机根。客户端 `LocalFileOperations` 是通用绝对路径，不提供项目根限制；现有签名任务领取和设备授权为可复用基础，不等于现有项目专用能力。
- `ConversationService` 禁止项目 Run 与普通本机客户端授权混用，`LocalProjectResourceAccess` 与 JDBC 来源检查保护现有协议 4。具体代码位置与数据流见设计。
- 现有 `LocalProjectToolCatalog` 用固定 `project_*` 目录登记 Server 本机工具，网关按稳定 ID 路由；ReAct/Harness 的项目载荷保护也依赖项目工具标记和 ID。因此客户端项目必须使用独立工具命名空间并接完所有受保护载荷通道。
- 当前根/项目每次登记都生成新随机 ID，未决操作和项目行锁按 `projectId` 判断；同一物理目录可通过不同 projectId、`--state-dir` 或重新配对绕过串行假设。远端项目还需将写前快照预算、写后幂等推进和迟到读取代次纳入合同。
- 现有命令服务会核对可执行文件和若干构建配置，但远端 Run 不能直接套用 Server 本机无界完成等待、进程树或人工 `UNKNOWN` 收口语义。项目页也把能力、同步列表和三种授权模式绑在单一 `/api/projects` 合同上，需独立来源分栏和异步响应适配。
- 采用设计中的 A1–A4 自主假设：首版 Windows x64 交互客户端、单实例 JDBC 非生产 Server；实际读写/条件撤销/固定工具链命令；逐次副作用审批；HTTPS 与设备签名。均非用户已确认事实。
- 保留既有 Server 项目和普通会话，禁止自动切换根；不承诺项目文件不经过 Server/模型，不实现生产/跨平台/OS 沙箱/多人共享。功能默认关闭。
