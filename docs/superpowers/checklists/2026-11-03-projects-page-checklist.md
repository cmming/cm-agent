## 需求与范围

`projects.html` 是本地项目工作台，负责：

- 在运行 Server 的电脑上通过系统选择器登记本地文件夹为项目。
- 列出、刷新、改名校验、归档和查看项目。
- 浏览目录、分页加载、搜索文件名和脱敏正文、预览文本并把文件引用到会话。
- 在项目下创建多个会话，会话固定绑定当前项目和所选 Agent。
- 新建会话时自动安装并授权固定 `project_*` 工具目录。
- 在服务端能力允许时，可通过“登记固定项目工具目录”兼容入口显式登记固定目录；该操作只登记定义，不代表已向 Agent 授权。
- 为每轮 Run 选择 `ASK_ON_EFFECT`、`ASK_ON_RISK` 或 `FULL_ACCESS`。
- 处理文件变更提案、撤销提案、命令提案、运行状态、停止和 UNKNOWN。
- 处理原生文件夹选择、项目创建、改名和归档的未知结果，不自动重复提交。
- 在桌面和窄屏下保持项目、会话、文件三类工作区域可用。

非目标：远程文件夹浏览、浏览器所在电脑的路径访问、操作系统级沙箱、桌面 GUI 自动化、多人协作、自动 Git 操作。远程电脑访问属于 `local-client.html` 需求组。

## 核心验收

| 编号 | 通过标准 |
|---|---|
| A1 | 页面能力说明与当前服务实际启用的项目工具一致，不把未配置能力显示为可用 |
| A2 | 项目登记、列表、刷新、改名、归档和重新读取不产生路径穿越或跨 owner 访问 |
| A3 | 文件树、搜索、预览和引用遵守项目根、脱敏和预算限制 |
| A4 | 新建会话自动准备固定工具，但不覆盖已有合法 grant，不接受浏览器提交工具 ID |
| A5 | 三种授权模式只作用于固定项目工具和当前 Run；普通工具不继承项目授权 |
| A6 | 文件/命令在副作用前复核 Run、模式、提案版本/摘要、权限和审计 |
| A7 | 停止、审批拒绝、过期和失败不自动重放；UNKNOWN 先核对 |
| A8 | 页面错误有可读中文原因、稳定错误码/编号，并与后台日志可关联 |
| A9 | 桌面和窄屏下主要控件、消息、文件名和按钮不重叠、不产生非预期横向溢出 |
| A10 | 历史证据的应用范围明确；后续源码变化或未验证平台不被旧通过覆盖 |
| A11 | 工具目录手工登记仅在能力允许时显示；只登记固定定义，不自动授予 Agent，不覆盖已有合法授权 |
| A12 | 选择、创建、改名和归档在超时、版本冲突或响应未知时提示核对，不自动重复提交或伪造成功 |

## 执行边界

- 项目根由服务端保存的加密根和项目身份决定，浏览器不能提交任意绝对路径。
- 项目命令在 Server 所在电脑上以运行账号执行，不提供操作系统级隔离；页面必须明确这一事实。
- 项目内 `FULL_ACCESS` 只自动批准已识别的固定 `project_*` 工具，不等于设备客户端完整访问。
- 任何真实写入、命令、构建、模型调用和服务重启都必须重新核验授权与证据，不复用历史 Run。
