- `.gitignore`：仅新技能目录纳入可跟踪范围，其余 `.agents` 内容保留原忽略语义。
- 原六份 `next-iteration` 分析产物：前两份迁入专用目录，统一 `next-iteration-analysis` 主题，链接修正，原分析基线保留并引用后续 A 批次账本。
- 本次 `requirement-workpack-skill` 六份工作包：按新契约生成并记录本次改造，作为实际使用案例。

## 方案差异与边界

R1 实际实现 T9：技能新增“需求迭代优化”流程及调用示例，先定位既有工作包、读取六份及证据，再审查需求质量、分类差异、评估任务/决定/验收影响。契约规定六份保持原路径及共同修订号；取消保留旧状态，完成项条件变化追加关联验证，用户确认的决定仅在明确变更后替代。元数据支持生成或迭代入口，AGENTS.md 同步规则。迭代继承目标包模式，不因“优化”开启交互；默认目标歧义不能用文件时间猜测。当前提示词只推进最新范围有效未完成项。

本工作包作为实际维护案例，从本轮前文件建立 R0，再同步为 R1，追加 T9/T10，未重排 T0～T8、另建六份或覆盖既有证据。此处实现是技能指令与需求文档维护，不是 JSON 导出等模拟业务代码实现，也未执行回滚、提交、推送或部署。

R1 验收 T10：独立执行者 `/root/workpack_iteration_forward_test` 不继承主智能体结论，只读取当前入口和契约，生成 G～I 三组真实回复及六份虚拟摘录。主智能体复核明确变更保留旧测试并增加新验收、交互保留既有决定等待新选择、目标不明不覆写最近文件。证据在账本；真实用户输入工具和通用业务执行仍未回放。

连续验收 T8 已完成：使用独立子智能体，仅提供当前技能、产物契约和虚拟审计查看器事实，生成五个初始场景以及一次实际选项答复的后续场景。主智能体核对六个实际回复，未发现需要调整模式主规则的问题；观察到未答复保持未决、关闭交互记录自主假设、选择 JSON 后继续为导出范围提供选项。文字证据保存于本任务账本；未调用真实用户输入工具、创建虚拟业务文件或执行业务代码。

2026-10-01 连续实现：技能增加 `mode=default` 与 `mode=interactive`，未指定直接使用默认且不咨询模式；当前任务显式开启/关闭才能切换，引用或讨论不会触发。默认自主取舍并记录假设与阻塞；交互模式给 2～3 个明确选项，待真实答复后再完成相关决定。产物契约、AGENTS.md、默认调用元数据同步，执行提示词和快捷问答传递当前模式。沿用本工作包补充 T7。未改业务代码或其他在途文件，本轮模式修改未提交。
