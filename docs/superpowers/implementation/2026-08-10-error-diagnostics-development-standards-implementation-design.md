# 错误诊断开发规范实现说明

## 最终实现

根级 `AGENTS.md` 新增“错误诊断、日志与前端提示规范”，将错误处理从单一的错误响应安全要求扩展为完整排查闭环：

```text
前端脱敏原因 + errorCode + errorId
                    ↓
后台按 errorId 检索结构化失败日志
                    ↓
根据 tenant、资源、操作、状态和脱敏堆栈定位原因
```

规范要求优先复用已有请求或业务调用标识，定义前端可见与不可见信息，规定日志记录边界和必需上下文，区分日志级别与安全审计，并明确失败分支的测试断言。

测试规则增加交叉约束：凡是修改错误处理、异常转换、重试、降级或前端失败提示，必须同步验证错误码、错误编号、日志关联和脱敏。

## 关键位置

- `AGENTS.md#错误诊断、日志与前端提示规范`
- `AGENTS.md#测试规则`

## 与原方案的差异

原始需求只要求方便通过日志和前端错误信息定位。实际规范进一步补充了可信上下文来源、日志级别、单次堆栈边界、审计职责以及评审禁止项，避免实现为了“更详细”而泄露凭据或重复记录异常。

## 运行时影响

本任务只改变仓库开发治理规则，不直接改变 API、页面、日志输出、数据库或部署行为。后续代码改动需要遵循该规范。
