# 本机客户端项目工作区实施计划

日期：2026-11-09；当前修订 R2（2026-11-09）；mode=default。仅为待执行方案；[清单](../checklists/2026-11-09-client-project-workspace-checklist.md) 是验收权威，详见[设计及 R1/R2 差异](../specs/2026-11-09-client-project-workspace-design.md)；另见[提示词](../prompts/2026-11-09-client-project-workspace-prompt.md)、[实际交付](../implementation/2026-11-09-client-project-workspace-implementation-design.md)、[账本](../progress/2026-11-09-client-project-workspace-ledger.md)。原 T0–T9 记录保留，R1 补充 T10–T14，R2 继续补充 T15–T18 并扩展 T9/T14；R2 与旧修订冲突时以 R2 为准。

1. **T0 基线与边界**：复核 `.codegraph`、当前源代码及目标操作系统、工作树、子目录规范、运行模式和迁移最高版本。绘制项目来源及所有会话/Run 派生入口清单，列出文件系统原子性、撤销能力和传输信任假设。验证现有客户端单线程轮询对交互窗口和取消的影响，先设计并发而非在轮询线程无限阻塞。
2. **T1 选择器**：给客户端添加能力版本与受控交互任务、桌面 UI 和原生目录选择适配；绑定用户确认及关联码。测试无桌面、忙碌、超时、重复、取消及旧版能力；保留原客户端功能。
3. **T2 登记协议和存储**：新增 pre-Run 控制请求、设备签名回执、单次票据与双端恢复；设计客户端私有存储、迁移和服务端事务边界。只保存根标识和摘要至 Server，不返回绝对路径。测试跨主体、跨设备、重复消费、重启/丢消息；Rocky 上 PostgreSQL/MySQL 迁移及原生注释验证。
4. **T3 来源与执行编排**：新增 client-project 的来源见证、项目/会话/Run 固定绑定及专用任务通道；完整接入读取、取消、审批、历史、产物和列表，失败关闭；保留协议 4 和普通本机客户端互斥。服务端读写短事务，客户端及模型 I/O 均在事务外；验证所有访问与损坏来源路径。
5. **T4 项目读取**：客户端增加安全根目录执行器，优先评估抽取可复用无 Server 依赖的安全原语；若不能满足实际平台验证则不开放。实现版本化目录、预览、搜索及 Run 读取快照，并验证实体目录替换/硬链接/重解析点/预算和 `partial`。
6. **T5 文件操作**：实现客户端持久日志、精确预览和 conditional apply/undo；Server 冻结审批摘要、幂等任务与回执。以并发改动、崩溃、部分应用、设备中断、重复派发验证；不把 UNKNOWN 自动改为失败或重试。
7. **T6 受控命令**：客户端管理本地显式固定工具链和可执行文件身份；实现提议、精确预览、逐次批准、运行、输出和结束核对。验证超时、停止、进程树、断线；UI 展示无 OS 沙箱。
8. **T7 生命周期**：定义选择、项目、任务和授权各自状态与原子条件更新，覆盖撤销/归档与任务竞争、服务端/客户端重启、ACK 丢失、设备身份丢失；对无法证明发生结果的任务保持 UNKNOWN。细化日志、审计和清理保留策略。
9. **T8 交互与文档**：扩展 `projects.html`、`local-projects.js`、`project-development.js`，增加设备来源、可用状态、关联码、项目级操作进度和审批预览；移动端/键盘/错误及旧页面回归。同步 README、配置、运维和 release-notes，保留默认关闭及限制。
10. **T9 端到端**：Java 21/Maven 环境检查后运行关联模块测试与 JS 测试；双库/Testcontainers 按 AGENTS 在 `ssh rocky` 受控环境执行，先确认 Docker、JDK 和远端工作区与待测提交及差异一致。Windows 真机用户桌面与另一台 Server 完成选择、开发、审批、断线和重启验证；缺条件明确记录原因和未执行门禁。

实施时重新核实类名、路由、约束及测试命令，避免把上述文件线索和候选协议值当作现有实现。按实际结果更新实施任务自己的工作包并引用本需求包；未经明确授权不提交、推送或部署。

## R1 新增实施步骤

11. **T10，依赖 T0**：在本机项目 Bean 之外明确客户端项目开关、受支持 Server 平台和 Runtime 保护合同；清点协议 4 所有判断，设计停机升级、关闭开关拒绝和不可混版/回滚栅栏；以两种数据库和不同 Server 平台验证。
12. **T11，依赖 T1/T2**：分离选择、项目只读和 Run 副作用三类任务，建立有界控制/执行并发、精确身份和双端持久状态；在长命令中验证取消通道可用；注入选择超时、重复及 ACK 丢失。
13. **T12，依赖 T3/T11**：以同一事务锁序处理启动许可与撤销/归档竞争，记录本地持久账本；覆盖许可先提交和撤销先提交，以及旧设备回执不可认证的人工核对路径，明示许可后的撤销窗口。
14. **T13，依赖 T4/T5**：将原始字节哈希、脱敏视图与完整审批摘要分开；设计掩码遮挡变更时拒绝批准，覆盖文件、命令及提示注入；明确数据留存和日志脱敏。
15. **T14，依赖 T10–T13**：建立入口/身份/开关、故障崩溃、许可/撤销竞争、版本/升级四张矩阵，逐行关联验证代码和真实环境证据，结果供 T9 汇总。R1 未改变 R0 产品范围；T9 现须同时依赖 T10–T14。

## R2 新增实施步骤

16. **T15，依赖 T0/T3**：定义独立、租户稳定的 `cm-agent/client-project/v1` 工具 ID 和 `client_project_*` 模型名，固定 ID→种类→权威来源→Run 目录→权限/风险的网关路由。先为 ReAct/Harness 建立强类型、来源感知的载荷保护合同，再实现工具；覆盖输入、进度、失败、思考、审批、最终消息、ToolCall、SSE 和加密检查点。以敏感标记测试关闭/旧版/普通会话/调试/MCP 的伪造名称和旧 ID，以及成功、异常、超时、审批恢复路径。该步骤先于 T4/T13 的工具接线。
17. **T16，依赖 T0 并同步约束 T2**：在客户端建立当前 OS 用户范围的实际根身份、路径别名、祖先/后代重叠登记和跨进程持久锁；`--state-dir`、重复配对、不同 Server 和新 rootId 不得形成并列冲突域。为每个项目意图持久化串行代次、旧许可拒绝和根隔离状态；UNKNOWN、已许可、命令存活证据不足均阻止重叠根新副作用。接入写前 Run 快照预算、已验证写后回执的幂等推进、部分成功、删除/移动见证和迟到读取代次。以重解析点、大小写、对象替换、相同目录多登记和崩溃真机测试验收。
18. **T17，依赖 T3/T6/T7**：增加远端 Run 完成屏障和命令生命周期适配。模型结束仅表示不再产生新工具调用；关联命令全部退出或进入明确失败/UNKNOWN 前不得 SUCCEEDED。使用有界、可中断且不占 JDBC 事务/HTTP 线程的等待；超预算进入既有失败/unknown 收口并保持根隔离。终态撤销新执行许可但保留受限停止、状态查询和对账，禁止从这些入口重启命令。人工终结只结束逻辑意图；释放物理隔离须证明旧许可失效且进程静止。执行前复核工具链定义、可执行文件、argv、工作目录、环境及构建配置摘要，并披露未冻结依赖风险。
19. **T18，依赖 T3/T8/T11**：把项目页拆成 Server 本机与客户端项目独立来源分栏，分别请求 capability/列表/详情；旧 `/api/projects` 合同保持，客户端候选路由 `/api/client-projects` 实施前核对。增加 202→轮询→终态响应适配，所有请求绑定 sessionEpoch、主体、来源、设备、项目/root 版本、会话和 UI 加载代次。导航/退出/切项目后丢弃迟到结果；AbortController 不宣称取消服务端任务。后端拒绝客户端来源的 ASK_ON_RISK/FULL_ACCESS。离线/撤销/根失效时区分历史读取与当前能力，来源损坏、跨主体和权限撤销仍拒绝。
20. **T14/T9 汇总**：把 R2 C01–C10 并入入口/身份/开关、故障时序、许可/撤销和版本升级矩阵；T14 列出代码、自动化与真实环境证据，T9 在 Windows 真机、另一台 Server、真实 Provider、Rocky 双库和浏览器代际条件下完成最终验收。任何未验证项保持待做或阻塞，不以文档修订表示能力可用。
