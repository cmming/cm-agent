# docs 可用性复核计划

日期：2026-11-17；主题：`docs-usability-review`；修订：R2（2026-11-17）；模式：`mode=default`。

1. T0：读取 Git 状态、文档入口和历史复核；并行检查生产文档导航与代码配置。
2. T1：在入口增加按任务深链接，并在长文新增场景目录；检查目标章节和锚点。
3. T2：对照当前及提交基线配置，定点澄清默认值与覆盖；不复制敏感内容。
4. T3：维护六份产物，检查链接、空白、修改边界及验证限制；记录实际结果于账本。

## R1 后续复核

5. T4：并行核对使用文档、配置、源码、原始需求和现有验收账本；保留差异及证据。
6. T5：只修改有依据的问题，必要时同步关联入口，历史条目只追加后继说明。
7. T6：检查 docs 本地链接和锚点、修改文件空白及 R1 文档一致性；将实际结果与限制记录到账本。

## R2 重复内容整理

8. T7：并行审查现行文档和历史导航中的重复，确认各段职责与唯一内容。
9. T8：以概要和深链接替换确认可合并的正文，保留原章节、条件、独有证据和历史记录。
10. T9：逐项检查被缩减内容已保留或有对应来源，核查链接、锚点和工作包一致性。
