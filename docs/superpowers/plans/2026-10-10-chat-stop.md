## 实施前必须明确的技术问题

1. 停止登记、运行派发和终态落库的竞争顺序，尤其正常结果不得覆盖已经登记的 CANCELLING。
2. 模型等待期间如何接通实际 AgentScope 2.0.2 的订阅取消/interrupt；不能只等待下一个 delta 检查。
3. 在途工具忽略中断的等待与诊断策略、当前会话运行互斥及孤立状态收口。首版单实例限制写入生产说明。
4. 部分正文服务端快照大小上限、已保存审批消息的复用、停止后的上下文标注；文件产物停止后的清理不得开放下载。
5. PENDING 撤销与批准/过期/创建新审批的 CAS 或事务一致性；已接受决定保留原历史。

这些问题先在 T1/T3 落到契约与测试方案。影响已确认 D1～D3 或拓展部署承诺时，在交互模式下提供选项确认；一般工程细节无需逐步许可。

## 验证安排

- 文档阶段：文件数量、统一元数据、任务状态、相对引用、提示词路径及空白检查；不执行 Java 或模型测试。
- 实施前：`java -version`、`mvn -v`，确保 Java 21；本项目没有 Maven Wrapper。
- 快速测试：按 T1～T5 改动选择 core、adapter、console 及 server 的定向测试。参考命令 `mvn -pl cm-agent-core,cm-agent-agentscope-adapter,cm-agent-console -am test`；server 使用 `-Dtest=<已核实的相关类>` 和 `-Dsurefire.failIfNoSpecifiedTests=false`，避免本机误跑数据库测试。最终运行的完整命令必须写入实施账本。
- 数据库：涉及 JDBC/Flyway/Testcontainers 的测试全部经 `ssh rocky` 在 Rocky 容器执行，镜像 `maven:3.9.9-eclipse-temurin-21`，数据库 PostgreSQL `16-alpine`、MySQL `8.4`。先确认 Docker/JDK 21、远程 HEAD 与待验证本地提交一致，并单独核实未提交源码一致性；不能只用同一 HEAD 宣称工作树相同。远程路径由实际环境确认。
- 新 schema：只新增迁移，两个方言版本一致，表/字段中文原生注释及双数据库注释验证齐全；若不需迁移记录理由。
- 浏览器：显式 test/local profile、确认资源加载，桌面与 390×844 上执行发送→停止→刷新→续聊、审批停止、批准与停止竞争、网络不确定等交互；截图配合后台实际调用计数和状态检查，单凭按钮外观不能通过。
- 真实模型：验证模型流停止与工具阶段停止，不把 FakeRuntime 或 Stub 通过当成 Provider 验收。凭据只用于验证，不写入文档、命令输出或仓库。
