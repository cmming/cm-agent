# 可直接复制给 Codex 的执行提示词

下面代码块是完整提示词。使用时在 CM Agent 仓库中新建聊天并粘贴；本文件的生成不表示已经执行清单。

这是原分析工作包的执行输入示例，已完成的 A 批次结果见 [审批主动过期验收账本](../progress/2026-09-30-approval-expiry-a-ledger.md)。后续使用时先核实当前实现与剩余任务，避免重复执行。此次归档仅更新路径和当前文档规则，原需求与分析边界保持不变。

```text
请在 F:\java\cm-agent 中，按照 docs/superpowers/checklists/2026-09-30-next-iteration-analysis-checklist.md 的 A 批次 T0～T8，核实当前已实现和已验收项，完成剩余审批主动过期收口与关键流程验收任务。请实际修改必要的代码、测试和文档，持续推进到验收或明确记录外部阻塞，不要仅给分析、方案或伪代码。

执行边界：
1. 只执行 A 批次。B、C、D 是后续方向，本轮不实现执行租约、自动重放、独立审批中心或新业务功能。允许为 A 所必需的局部重构，禁止依赖升级、无关重构或放宽权限。
2. 先读取适用的 AGENTS.md、模块 POM、README、配置说明、运维说明和清单。仓库有 .codegraph 时先用 CodeGraph 定位代码；若结果不完整或不匹配，说明限制并直接复核当前文件。不要凭旧记忆重做已经交付的技能发布功能。
3. 核对 git status 与 HEAD，理解相关已有改动。保留用户 application*.yml、.codex/、.workbuddy/ 等无关内容，不打印敏感配置。不使用 git add -A、git restore . 或全局 reset。
4. 使用独立 codex/ 分支或适合的隔离工作树，不动用户运行中的服务；测试用隔离端口。先完成 T0 执行设计，合理工程细节自主决定，然后按依赖顺序实施，不为每一步重复询问许可。
5. 清单中的文件位置是当前线索，先核实再修改。每项标记为待做、进行中、完成或阻塞；已实现项也要核验证据，不能凭文字勾选。修改失败处理、安全边界、领域字段和框架隐式行为时，按 AGENTS.md 同步落地中文注释及测试。

子智能体协作：
- 允许按需使用子智能体，是否委派由主智能体根据独立任务、依赖和协调成本决定；不为满足数量而启动，也不要求全程并行。建议同时启用 1～2 个子智能体。
- 主智能体统一负责 T0 设计、T1～T3 核心契约与实现、集成和最终验收。核心链路由主智能体保持一致，子智能体可独立审查并发、事务和安全边界；契约稳定后，可委派明确范围的测试补充、控制台修改或浏览器验证。
- 委派前明确任务、输入契约、负责文件和验收条件，避免多个智能体同时修改同一文件；共享工作区时保留其他智能体的改动。存在依赖的任务按顺序推进，避免重复读取、重复实现或重复运行相同测试。
- 同一 Rocky 验证环境由一个指定智能体统一操作；主智能体审查子智能体的代码和证据后统一完成集成验证，不能仅汇总报告就宣布完成。
- 子智能体能力不可用，或当前没有值得委派的独立任务时，由主智能体继续完成工作，不因无法并行而阻塞。使用协作工具执行当前任务的子任务，不为此创建用户侧新聊天。

必须保持的行为：
- 主动扫描同时处理会话审批和独立 TEST Run 审批。扫描与决定通过数据库条件更新竞争，失败方不得收口 Run、删除检查点或执行工具。
- 系统任务身份来自服务端；跨租户发现只在系统边界内，单项操作仍使用可信资源归属。系统扫描不能冒充发起用户，也不能凭保存的旧权限恢复工具。
- JDBC 中过期标记、等待 Run 收口、该 Run 检查点清理和严格审计保持短事务一致性。审计/持久化失败回滚并可诊断，不吞异常；单项失败不阻断其他候选。
- 不调用 Runtime 或外部工具处理过期。批准不等于执行成功；本轮不自动恢复结果不确定的已批准运行，也不承诺外部副作用恰好一次。
- 保留多租户、RBAC、发起人审批、工具授权重查、技能快照与发布门禁、TEST 不写正式会话/消息的现有约束。
- 控制台通过权威查询恢复状态，刷新和断线不自动重复提交；只改相关提示与操作状态，保留现有中文工作台和 v1/v2 兼容。

验证与执行：
- 构建前确认 java -version 和 mvn -v。必要时配置 JAVA_HOME=F:\java\temurin21\jdk-21.0.11+10，再确认 Maven 使用 Java 21。
- 根据 T5 运行不依赖容器的定向测试和受影响 Node 测试。不要因为 CodeGraph 未发现测试就认为没有测试。
- Docker、Testcontainers、JDBC、Flyway 验证必须通过 ssh rocky，在项目隔离容器中使用 maven:3.9.9-eclipse-temurin-21、PostgreSQL 16-alpine 与 MySQL 8.4。先确认远程 Docker、Maven/JDK 与 Git 快照一致。为准确验证，可创建仅包含本轮相关文件的隔离本地验证提交；不推送、不合并、不部署、不清理无关容器或卷。
- 按 T6 验证事务回滚、双扫描竞争、扫描与决定竞争和重启后收口。全量测试含容器时也在 Rocky 执行；不得改成本机 Docker。
- 按 T7 使用隔离 fixture 和可控 Runtime 做真实浏览器流程，证明 PASSED 发布、版本绑定/回滚、TEST 审批恢复和主动过期。可控测试不是实际模型验收；没有安全专用测试配置时不要调用真实模型或有外部副作用的工具。
- 远程环境或凭据不可用时，记录确切错误和未执行项，继续可独立完成的任务；不要伪造通过，不把验证阻塞当作实现完成。只在确实需要人类提供缺失信息或处理阻塞时提出一个具体问题。

文档与交付：
- 为独立代码实现任务生成同日期、同主题的 docs/superpowers/checklists、prompts、specs、plans、implementation、progress 六份中文产物，持续更新实际状态；保留已有 next-iteration-analysis 六份文档作为形成清单的历史记录。若正在继续已有实施任务，按当前 AGENTS.md 复用和维护其工作包，不重复建立任务或重做已验收项。
- 更新 README、configuration、operations、release-notes；已解决限制可改为新行为，未解决的租约/异常恢复边界必须保留。
- 执行 git diff --check，检查本轮相关 diff、注释与敏感信息。未提交的交付明确写“未提交”；隔离验证提交与最终交付状态分别说明。
- 最终按“变更摘要、验证命令与结果、影响范围、风险与注意事项、后续建议”五项汇报，并给出 T0～T8 验收状态和证据路径。所有必需验收通过才可宣称 A 批次完成。不要仅因时间或上下文不足提前结束；恢复上下文后从账本未完成项继续。
```
