# 六份产物契约

所有路径相对仓库根目录，文档使用中文。生成时替换日期、主题和需求内容，最终产物不得遗留模板占位符。下面是内容契约，不要求机械保留所有标题；小需求可以简写，但六份文件的职责与事实边界保持完整。

## 单一状态源

- `progress` 账本是任务实时状态、实际验证证据、命令结果、阻塞、提交和发布信息的唯一入口。
- 清单、提示词、设计、计划和实现说明不得复制状态表、测试通过结论或提交状态；需要传播当前状态时，只链接账本并给出简短摘要。
- 实现说明可以记录“实际改了什么”和“与设计有什么差异”，验证能否证明目标达成由账本负责。
- 新工作包和后续修订直接遵守该规则。历史工作包保留旧内容；同一工作包再次修订时，只迁移本次实际触及的内容并在账本记录衔接，不批量改写历史。

## 事实来源与冲突处理

权威入口见[文档总入口](../../../../docs/README.md#当前事实来源矩阵)。核实实际行为时记录代码版本、相关配置来源和验证环境；核实预期行为时引用用户确认的需求、设计或 ADR 修订。发现不一致，在账本中说明双方依据、差异和采用理由；证据不足时保留未核实结论。生产说明回答当前如何使用，过程文档保存当时的决定与证据；术语表和 ADR 不承担任务实时状态。

## 工作包归档与恢复

工作包归档是责任结束后的逻辑归档，原日期、主题、路径、任务编号及历史正文保留。归档不表示已经提交、发布或在所有环境通过验收。

归档前逐项检查，满足以下任一条件才可在原账本记录“已归档”：

- 本工作包约定范围和验收已经结束；仍适用的限制完整保留。属于本包验收的未处理缺口不能仅改称限制后归档。
- 需求已被明确取消，记录取消来源、原因和已发生的影响。
- 剩余事项已逐项移交给明确的后继工作包，记录原任务、后继任务、承接范围与接受依据。仅有相关主题链接不等于移交。

账本的归档记录至少包含：核定日期、归档结论、责任范围、完成/取消/移交依据、验收与证据限制、后继入口（没有时明确无移交）。仍承担未解决事项的工作包可记录为“待续”；正在推进的记为“当前”。这些是工作包层面的归档结论，不替代任务状态、提交状态或发布状态。

索引只投影账本中的分类并链接依据，不另写测试结果或任务状态；每次核定同步更新导航。没有账本或没有明确归档结论时，索引显示“归档状态待核实”，这不等于业务未完成，也不补造旧账本。历史文档集合维持原状，不为归档批量补齐六份。

同一需求恢复时，先在原账本追加恢复日期、原因和采用范围，再按原文档集合追加修订，保留旧归档事实；范围或验收改变时同步清单、设计、计划和提示词。独立新需求另建工作包并关联原包。单纯追加归档事件不提升需求修订号，也不要求在其他五份复制归档状态。

## 历史纠错

- 当时正确、后来变化：保留当时结论，追加适用日期与后继入口。
- 当时已有错误或链接现已失效：定点修正，并留下日期、原因和依据；仓库外证据不可用时保留路径线索，不重建或臆造证据。
- 测试数字、验收范围和关键决定的原记录须可追溯；重要纠错保留原表述或明确的原文引用，不无痕覆盖。

## 模式与决定记录

六份文档标明相同工作模式：默认 `mode=default`，用户显式开启交互才使用 `mode=interactive`。执行提示词和快捷问答输入传递该模式，但用户新指令优先。

默认模式不主动征询选择，设计和账本记录自主假设、依据和影响；无法查实的外部条件记录为未验证或阻塞，不能假称用户确认。

交互模式先查证，再为未确定取舍给出 2～3 个选项及影响，收到用户明确选择后更新设计和账本的决定记录。决定表包含编号、问题、候选选项、状态、用户选择和影响；未答复用“待用户决定”，不按推荐项定稿。其他产物引用决定编号，依赖未决事项的任务保持待做或阻塞并注明对应决定，不另设“待决定”任务状态，也不标为完成。

| 产物 | 路径 | 核心职责 |
|---|---|---|
| 待办清单 | `docs/superpowers/checklists/<YYYY-MM-DD>-<topic>-checklist.md` | 稳定任务编号、范围、依赖、逐项验收和门禁 |
| 执行提示词 | `docs/superpowers/prompts/<YYYY-MM-DD>-<topic>-prompt.md` | 某一修订可复制、范围明确的执行输入 |
| 设计 | `docs/superpowers/specs/<YYYY-MM-DD>-<topic>-design.md` | 背景、目标、非目标、方案、决定与关键约束 |
| 计划 | `docs/superpowers/plans/<YYYY-MM-DD>-<topic>.md` | 实施顺序、文件、依赖和验证方法 |
| 实现说明 | `docs/superpowers/implementation/<YYYY-MM-DD>-<topic>-implementation-design.md` | 实际改动、关键位置及与设计的差异 |
| 进度账本 | `docs/superpowers/progress/<YYYY-MM-DD>-<topic>-ledger.md` | 实时状态、实际证据、未执行项、提交和发布信息 |

## 待办清单

写明需求来源、日期、Git 基线和当前范围。事实需附当前文件或已核实的证据路径，假设与未验证项显式列出。任务表至少包含稳定编号、目标、涉及文件、依赖、验收条件和验证方法；细节较多时可拆到任务小节。清单不维护待做、进行中、完成、阻塞等实时状态；这些状态及对应证据只记录在账本。若范围依赖已实现能力，先核验事实并在设计中说明，不复制执行状态。

列出必要门禁和任务依赖。后续建议仅当相关时给出，并明确是否纳入当前范围。通过相对链接关联其余五份产物；当前状态和证据只链接账本。

## 执行提示词

使用一个完整的 `text` 代码块承载提示词，开头写明仓库、需求、清单和当前任务范围；路径使用当前仓库可解析的真实路径。说明当前规范、关键安全与兼容约束、按依赖推进方式、账本作为权威状态与证据入口、失败处理要求、适用验证和外部阻塞处理。

交付要求引用六份文件，要求只把状态、命令结果和验证证据写回账本，保护无关修改和敏感信息，并遵循仓库最终输出格式。提交、推送或部署等操作不得获得用户指令以外的额外授权。合理工程细节自主决定，不要求逐步询问。代码块外说明生成提示词未执行它；关联另外五份产物和账本。

在代码块内写明当前模式：默认模式自主取舍并记录假设，不主动咨询；交互模式的未确定事项必须带选项询问，不把推荐或未答复当作确认。该要求与“无需逐步许可”不冲突，选项仅针对尚未确定的决定。

## 设计

记录背景、用户目标、范围与非目标、当前事实和假设、方案选择、数据或调用链、关键约束、验收标准。设计可以记录决定和替代关系，但不维护执行状态或验证结果。没有涉及数据库、事务或前端时，不为了套模板添加无关设计。关联另外五份产物。

## 计划

沿用清单编号，按依赖顺序记录具体操作、涉及文件、依赖和验证方式；任务不能只写“优化”“完善”而无可观察结果。说明不确定路径待复核。计划只描述方法和预期验证，不声称执行结果、完成状态或提交事实。关联另外五份产物。

## 实现说明

记录已经实际产生的代码或文档、关键位置、实际数据或调用链变化以及与设计的差异。只生成文档时，说明实际分析结论和文档产物；不得凭计划填入未来代码或假设成功。实施后更新为当前实际实现，并保留重要差异。测试是否通过、任务状态和提交信息不写入本文件，统一链接账本。关联另外五份产物。

## 进度账本

任务表沿用清单编号，并作为状态、实际证据路径、命令和结果的唯一入口；每项阻塞写确切原因、未执行验收和继续条件。区分当前运行、历史记录及尚未执行的测试，不能以代码完成代替验收通过。账本可以摘要其他五份文档内容，但完整方案、计划和执行输入仍链接原文件，不复制正文。

记录 Git 基线、相关改动范围、检查结果和遗留问题；未提交写“未提交”，提交后记录已确认的提交信息，本地验证提交与最终交付分别记载。关联另外五份产物。

## 一致性检查

- 同一工作包六份产物使用一致日期、主题、修订号、任务编号、范围和最新采用的验收标准。
- 相对链接解析到真实文件；代码围栏成对；敏感信息不进入文件。
- 实时状态、验证结果和提交信息只出现在账本；其他文件不得复制一套状态表。
- 实现说明必须对应实际产物及其与设计的差异。
- 文档任务和业务实施任务的状态只在账本明确区分；历史证据不冒充当前验证。

## 迭代产物契约

迭代继续维护原六份文件，工作包日期和主题不变；每份写明一致的当前修订号、实际修订日期和咨询模式。没有旧编号时以现有文件建立 `R0`，首个实际变更为 `R1`；编号递增，保留历史，不以复制六份新文件替代连续维护。修订记录集中在设计和账本，其余文件引用它们。

| 产物 | 迭代更新内容 |
|---|---|
| 清单 | 当前有效范围、仍有效任务、新增任务和变化的验收；保留原编号，移出项明确标注而非删除或写成完成 |
| 提示词 | 当前修订、最新采用范围、仍有效输入及验证；不执行移出项，不把历史通过算为本轮验收 |
| 设计 | 需求差异、调整前后、原因或来源、影响，以及假设与用户决定；被替代的已确认决定保留历史并关联新决定 |
| 计划 | 调整顺序、依赖、文件和验证方法，引用关联任务与修订；不重新安排未受影响的完成项 |
| 实现说明 | 实际代码或文档改动及与设计的差异；取消已实现需求不等于代码已回滚，新目标不等于已经实现 |
| 账本 | 修订号/日期/基线的唯一运行记录、差异采用状态、任务实时状态、决定变化、证据、旧证据适用性和验证缺口 |

修订差异表至少包含差异编号、类别（新增/调整/取消/澄清）、调整前后、来源或依据、影响任务/决定/验收、采用状态。交互模式的未决差异保持草稿；默认模式的自主调整记录假设依据，不能篡改用户确认历史。已明确的用户新指令可以替代旧决定，但须保留来源与替代关系。

任务状态仍使用待做、进行中、完成、阻塞；取消或被替代另用范围标记说明。旧任务不删、不重排、不重复利用编号；已完成项若因验收变化需要补充实施或验证，新增关联任务，不覆盖原完成证据。记录旧证据哪些仍适用、哪些不能证明新目标；未受影响的验收不机械重跑。没有新差异时无需增加修订号。

需求修订没有授予实施、提交、推送、部署或回滚权限。默认模式目标不明确时记录未确定，不通过最近文件名猜测并覆盖；交互模式提供候选工作包选项，答复前不改写依赖目标的内容。

## 交付快捷入口

最终回复除产物链接外，提供“使用本次提示词继续问答”。在 Codex 支持快捷跟进指令的界面，按下述格式输出未转义的列表项；示例中的三个路径占位符必须替换为本次实际生成、已验证存在的绝对路径，路径中的双引号必须转义，不能引用上一任务文件。该指令放在最终回复中，而非只写在 Markdown 文档中。

```text
- :codex-followup[使用本次提示词继续问答]{prompt="请读取 {提示词绝对路径}、{清单绝对路径} 和 {账本绝对路径}，将它们作为本次需求问答上下文。当前工作模式为 {mode=default或mode=interactive}，遵循该模式的咨询规则；后续明确切换模式时按用户新选择执行。先简要说明需求、范围和当前进度，之后基于这些文档回答我的后续问题。本轮进入问答模式，不执行提示词中的实施命令，不修改代码或文档，不提交、推送或部署。"}
```

快捷输入读取当前文件而非内嵌旧内容，便于持续更新后使用最新状态。提示词可能含有实施命令，问答模式仅将其作为上下文，不自动执行。缺失文件或内容冲突时明确说明，并先复核可用文件，不声称上下文已恢复。

无快捷跟进渲染能力时，改用提示词文件链接与一条含真实绝对路径的短输入，语义保持一致。最终可手动输入“请读取该提示词及关联清单、账本，进入本需求问答模式”。
