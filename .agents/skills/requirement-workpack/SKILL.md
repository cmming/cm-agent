# 需求工作包

将用户给出的一个需求转为当前项目可执行、可核验的六份中文产物。仓库规范优先；本技能只定义工作包的生成和维护，执行权限仍来自用户实际指令。

## 输入与范围

用户只需提供需求正文。仓库路径优先采用用户指定路径，否则使用当前工作区；日期取用户指定日期或当前会话日期；`topic` 使用简短英文小写连字符名称。同一独立任务复用已有日期和主题，独立新任务创建新工作包。

只要求生成工作包时，交付文档；用户已要求实施时，生成和维护文档不能替代已授权的实现工作。咨询行为由下面的工作模式决定。

## 工作模式

未指定模式时使用默认模式，不能为了选模式先询问用户。用户输入“开启交互模式”“交互模式”或 `mode=interactive` 时启用交互；“关闭交互模式”“默认模式”或 `mode=default` 时恢复默认。同一任务保留已选模式，显式新选择优先；新任务未指定时回到默认。模式适用于需求文档生成及围绕工作包的后续问答，不自动扩展实施权限。

只有针对当前任务的启用或切换指令改变模式；讨论技能规则、引用历史文档或给出调用示例本身不算开启交互。

生成新工作包与迭代既有工作包是任务类型，默认与交互是咨询模式，两者独立。迭代默认继承目标工作包已有模式，用户明确切换时覆盖；不能因为“优化”自动开启交互。

### 默认模式（mode=default）

- 不主动咨询、不弹选项、不要求用户确认普通方案或假设。先查当前证据，再选择符合需求和项目约定的保守方案，持续生成产物。
- 尚不能确认的内容写成假设、未验证项或外部阻塞，注明依据和影响；不得写成用户已确认或已验证事实。
- 无法自行获得的凭据、外部状态或授权不得编造或绕过；明确记录对应阻塞及继续条件，继续可独立推进的内容，不因普通不确定点停下来征询选择。

### 交互模式（mode=interactive）

- 优先查证能查证的事实。对现有指令和证据不能确定、仍需取舍的事项，必须提供选项让用户决定；不能仅抛开放问题，也不能自行将推荐方案当作用户决定。已明确的事项不重复询问。
- 每次聚焦一个决定，给出 2～3 个明确且互斥的选项，说明各自影响或代价；有推荐时将其放在首位并说明理由。保留用户自定义回答的空间，不人为限制合法选择。
- 工具可用时优先使用带选项的 `request_user_input_async`；该工具立即返回，仍需等待用户实际答复。工具不可用时用文字列出编号选项，语义相同。
- 未收到明确答复时保持“待用户决定”，仅推进不依赖该决定的分析；不得把预选项、超时或未答复视为同意，也不得发布依赖该选择的最终方案。所有选项都不能在现有约束下落地时，如实说明限制并提供可执行的缩小范围、补充信息或暂缓方案。
- 在设计和账本记录决定编号（如 `D1`）、问题、选项、用户选择及影响，其他文档引用已确认决定。用户切换回默认后，对仍未决事项依默认模式作出合理假设，明确记录切换与假设，不伪造用户选择。

## 生成过程

1. 核对适用 `AGENTS.md`、Git HEAD、工作树与暂存区，以及相关 README、模块 POM、配置和运维说明。保护已有改动，禁止打印凭据。存在 `.codegraph/` 时先用 CodeGraph 定位相关代码，结果缺失或不匹配再直接复核源文件与测试，并记录限制。
2. 将用户需求、当前事实、假设、未验证项分别记录。找到已实现能力及当前限制，避免重复实现；历史测试只能作为历史证据引用。
   同时记录当前工作模式；交互模式的未决事项按上面的选项流程处理，默认模式直接记录自主假设并继续。
3. 按实际依赖拆解任务，使用稳定编号如 `T0`、`T1`，数量随需求确定。每项注明目标、涉及文件线索、依赖、验收条件、验证方法和状态。未核实路径应标记为线索。仅当需求包含多阶段时划分批次，明确当前执行范围及后续方向。
4. 按 [六份产物契约](references/artifact-contract.md) 生成文件，统一日期、主题和任务编号。清单定义交付与验收；计划描述执行顺序；提示词使执行者能按范围推进；实现说明和账本如实记录当前完成工作。仅生成文档时不得把未来业务行为写成已有实现或测试通过。
5. 检查六份文件齐全、相对链接有效、任务依赖可执行、提示词范围与清单一致。区分待做、进行中、完成、阻塞；未运行的验证注明原因。检查本次差异与敏感信息，未提交明确写“未提交”。
6. 交付时给出本次提示词的文件链接和“使用本次提示词继续问答”快捷入口，按产物契约组装真实路径。用户点击后先读取提示词、清单和账本，建立本需求问答上下文，无需复制整段提示词。

## 提示词与维护要求

- 提示词引用仓库当前规范和六份文件，不复制大量容易过期的配置；仅加入该需求需要的权限、事务、兼容和副作用约束。
- 验证命令依据当前模块、环境和项目规则选择。CM Agent 的 Java 21、Rocky 容器验证等要求从当前 `AGENTS.md` 读取，不能把容器测试安排到本机 Docker。
- 遇外部环境阻塞时记录确切错误、受影响验收和仍可独立推进的任务；代码完成和必需验收通过分别记录。
- Git 提交、推送、合并、部署及外部系统操作的授权来自用户，不因生成执行提示词而获得。协作策略依据用户要求和当前能力，不为凑人数强制启动子智能体。
- 连续修改保持六份产物一致；后续独立实施任务引用原分析工作包，并建立自己的记录。历史基线和结论保留，不以最新实现状态覆盖原分析。

## 需求迭代优化

用户提出“迭代需求”“优化这个需求”“补充/调整/取消需求”或 `action=revise` 时，先识别目标工作包，再执行下面流程。仅讨论、解释或评审需求时回答问题或列建议，不因此直接改写文档；明确要求优化或调整则直接维护产物。

1. 用户指定主题或文件时使用该工作包；否则采用当前对话明确在讨论的工作包。缺少上下文且存在多个候选时，交互模式列选项确定目标；默认模式记录目标未确定，不猜测并覆盖最近修改文件，可先完成不依赖目标的分析。没有旧工作包时按新建流程生成，说明这是首版；目标独立的新需求建立新工作包并引用相关旧包。
2. 读取目标六份文件及当前实现/验证证据，整理已有范围、已确认决定、完成项和剩余项。评估目标与场景是否清楚、需求冲突或重复、范围是否过大、依赖是否成立、失败与验收是否可观察，以及当前约束下是否可实现；只提出和本需求有关的优化。
3. 将本轮差异分为新增、调整、取消和澄清，记录调整前后、来源或依据、影响的任务/决定/验收与理由。默认模式自主采用符合现有明确要求的保守优化；没有明确变更指令时保留用户已确认决定，将与其冲突的建议列为未采用。交互模式的未确定取舍必须提供选项，答复前保持草稿，不能伪造用户选择。
4. 复用原工作包日期、主题和六份路径，追加本轮修订 `R1`、`R2` 等及实际修订日期；缺少历史编号时从当前文件建立 `R0` 基线，不臆造旧修订。保留任务编号且不回收，新任务从最大编号继续；取消项保留旧状态和证据，并标明“移出当前范围”，不当作已完成。已完成项的验收发生变化时保留历史完成结果，增加关联修订待办和新的验证要求，不能把旧通过算作新通过。
5. 按 [迭代产物契约](references/artifact-contract.md#迭代产物契约) 同步六份文档。当前方案和执行提示词反映已采用的最新范围，只包含仍有效的待办，不执行移出项或重做历史完成项；实现说明区分需求修订和真实业务实现，账本保留修订差异、决定替代关系及证据适用范围。
6. 检查六份修订号、范围、任务与决定引用一致，输出本轮调整摘要、受影响待办和待验证项；快捷问答读取更新后的同一提示词文件，并带当前模式。没有实质变化时记录复核结论，不为了凑迭代制造新任务、版本或整套文件。

需求迭代授权仅覆盖用户要求的分析和文档调整；用户明确要求实施时继续对应实施工作，不因修订提示词就执行代码、回滚已交付功能或获得外部操作授权。

## 用法

用户可输入：`使用 $requirement-workpack，需求：聊天页需要让人工审批入口清晰可用。生成工作包，暂不实施业务代码。`

开启交互：`使用 $requirement-workpack，开启交互模式。需求：……。不确定的地方给出选项，由我决定。`

恢复默认：`关闭交互模式，剩余事项按项目约定自主判断并记录假设。`

迭代需求：`使用 $requirement-workpack，迭代优化 audit-export 工作包：导出改为 JSON，取消独立导出页，补充脱敏验收。只更新需求文档。`

交互优化：`使用 $requirement-workpack，开启交互模式，优化 audit-export 工作包的导出范围和验收标准。`

原型案例是仓库的 `docs/superpowers/checklists/2026-09-30-next-iteration-analysis-checklist.md` 及其五份关联文档。需要查看复杂任务拆解实例时读取该案例；其中审批扫描、T0～T8 和批次划分是案例内容，不是所有需求的固定要求。

## 快捷问答

在支持 Codex 快捷跟进指令的界面，最终回复输出一个未转义的 Markdown 列表项，使用 `:codex-followup`，名称为“使用本次提示词继续问答”。其 `prompt` 必须使用本次实际生成并已检查存在的提示词、清单、账本绝对路径，不填写模板占位符，不复制提示词全文。具体格式见 [交付快捷入口](references/artifact-contract.md#交付快捷入口)。

快捷输入要求读取上述三份文件，概括需求、范围和当前进度后，基于这些内容回答用户后续问题。问答模式把执行提示词作为需求上下文，不自动执行其中的实施命令，不因点击入口新增修改、提交、推送或部署授权。用户后续明确要求修改或实施时，再按实际指令和仓库规范继续。

快捷输入还应带上本工作包当前模式（`mode=default` 或 `mode=interactive`）；用户后续明确切换时按新选择执行。进入问答和开启交互是不同维度：默认问答直接回答并标注假设，交互问答中的未确定取舍需要给出选项。

界面不支持快捷跟进指令时，输出可点击的提示词文件链接，并提供一条包含真实路径的简短“读取此提示词并进入需求问答”输入，仍无需手工复制整段文件。
