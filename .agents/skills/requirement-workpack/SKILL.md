# 需求工作包

将用户给出的一个需求转为当前项目可执行、可核验的六份中文产物。仓库规范优先；本技能只定义工作包的生成和维护，执行权限仍来自用户实际指令。

## 输入与范围

用户只需提供需求正文。仓库路径优先采用用户指定路径，否则使用当前工作区；日期取用户指定日期或当前会话日期；`topic` 使用简短英文小写连字符名称。同一独立任务复用已有日期和主题，独立新任务创建新工作包。

仅缺少会改变目标或验收标准的关键信息时提出具体问题，并先继续不依赖答案的分析。日常工程细节自主决定，明确记下合理假设。只要求生成工作包时，交付文档；用户已要求实施时，生成和维护文档不能替代已授权的实现工作。

## 生成过程

1. 核对适用 `AGENTS.md`、Git HEAD、工作树与暂存区，以及相关 README、模块 POM、配置和运维说明。保护已有改动，禁止打印凭据。存在 `.codegraph/` 时先用 CodeGraph 定位相关代码，结果缺失或不匹配再直接复核源文件与测试，并记录限制。
2. 将用户需求、当前事实、假设、未验证项分别记录。找到已实现能力及当前限制，避免重复实现；历史测试只能作为历史证据引用。
3. 按实际依赖拆解任务，使用稳定编号如 `T0`、`T1`，数量随需求确定。每项注明目标、涉及文件线索、依赖、验收条件、验证方法和状态。未核实路径应标记为线索。仅当需求包含多阶段时划分批次，明确当前执行范围及后续方向。
4. 按 [六份产物契约](references/artifact-contract.md) 生成文件，统一日期、主题和任务编号。清单定义交付与验收；计划描述执行顺序；提示词使执行者能按范围推进；实现说明和账本如实记录当前完成工作。仅生成文档时不得把未来业务行为写成已有实现或测试通过。
5. 检查六份文件齐全、相对链接有效、任务依赖可执行、提示词范围与清单一致。区分待做、进行中、完成、阻塞；未运行的验证注明原因。检查本次差异与敏感信息，未提交明确写“未提交”。
6. 交付时给出本次提示词的文件链接和“使用本次提示词继续问答”快捷入口，按产物契约组装真实路径。用户点击后先读取提示词、清单和账本，建立本需求问答上下文，无需复制整段提示词。

## 提示词与维护要求

- 提示词引用仓库当前规范和六份文件，不复制大量容易过期的配置；仅加入该需求需要的权限、事务、兼容和副作用约束。
- 验证命令依据当前模块、环境和项目规则选择。CM Agent 的 Java 21、Rocky 容器验证等要求从当前 `AGENTS.md` 读取，不能把容器测试安排到本机 Docker。
- 遇外部环境阻塞时记录确切错误、受影响验收和仍可独立推进的任务；代码完成和必需验收通过分别记录。
- Git 提交、推送、合并、部署及外部系统操作的授权来自用户，不因生成执行提示词而获得。协作策略依据用户要求和当前能力，不为凑人数强制启动子智能体。
- 连续修改保持六份产物一致；后续独立实施任务引用原分析工作包，并建立自己的记录。历史基线和结论保留，不以最新实现状态覆盖原分析。

## 用法

用户可输入：`使用 $requirement-workpack，需求：聊天页需要让人工审批入口清晰可用。生成工作包，暂不实施业务代码。`

原型案例是仓库的 `docs/superpowers/checklists/2026-09-30-next-iteration-analysis-checklist.md` 及其五份关联文档。需要查看复杂任务拆解实例时读取该案例；其中审批扫描、T0～T8 和批次划分是案例内容，不是所有需求的固定要求。

## 快捷问答

在支持 Codex 快捷跟进指令的界面，最终回复输出一个未转义的 Markdown 列表项，使用 `:codex-followup`，名称为“使用本次提示词继续问答”。其 `prompt` 必须使用本次实际生成并已检查存在的提示词、清单、账本绝对路径，不填写模板占位符，不复制提示词全文。具体格式见 [交付快捷入口](references/artifact-contract.md#交付快捷入口)。

快捷输入要求读取上述三份文件，概括需求、范围和当前进度后，基于这些内容回答用户后续问题。问答模式把执行提示词作为需求上下文，不自动执行其中的实施命令，不因点击入口新增修改、提交、推送或部署授权。用户后续明确要求修改或实施时，再按实际指令和仓库规范继续。

界面不支持快捷跟进指令时，输出可点击的提示词文件链接，并提供一条包含真实路径的简短“读取此提示词并进入需求问答”输入，仍无需手工复制整段文件。
